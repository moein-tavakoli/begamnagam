# بگم نگم

یک بازخورد کوچک، با احترام بیشتر. وب‌اپ فارسی برای فرستادن یادآوری‌های محترمانه یا قدردانی از طریق پیامک، بدون نمایش هویت فرستنده به گیرنده و بدون ایجاد گفت‌وگوی مستقیم.

این مخزن نسخهٔ محلی و آزمایشی محصول است. پرداخت، کد ورود و تحویل پیامک شبیه‌سازی می‌شوند؛ هیچ پولی جابه‌جا و هیچ پیامک واقعی فرستاده نمی‌شود. حالت پیش‌فرض، متن آمادهٔ بررسی‌شده است؛ با تنظیم Ollama، مدل محلی متن مناسب را از بین نمونه‌های بررسی‌شده انتخاب می‌کند. ادعای ناشناسی مطلق یا تضمین ناراحت‌نشدن گیرنده نداریم.

## وضعیت فعلی پیاده‌سازی

فاز یک محلی با ظاهر فان و رنگ‌بندی مرجع کارفرما پیاده‌سازی شده و برای بررسی آماده است؛ [گزارش تحویل و موارد باز](docs/phase-one/README.fa.md) و [قواعد طراحی](design-system/begamnagam/MASTER.md) را ببینید. پذیرش کامل G1 به build کامل Compose روی محیط پاک وابسته است و فعلاً باز است. مدل‌های مستقل مالی/ارسال اسکلت فاز یک‌اند؛ اتصال آن‌ها به checkout در فاز بعد انجام می‌شود. فاز دو و سرویس واقعی هنوز مجوز ندارند.

## اجرای سریع

پیش‌نیاز: Docker با Compose جدید، Python 3 برای ساخت تنظیمات و تست دود. استفاده از `make` اختیاری است.

```sh
python3 scripts/init-local.py
docker compose up --build -d --wait --wait-timeout 300
python3 scripts/smoke.py
```

- محصول: <http://localhost:3000>
- پنل مدیریت: <http://localhost:3000/admin/>
- سلامت بک‌اند: <http://localhost:8000/healthz>

ساخت مدیر بدون حساب یا رمز از پیش تعیین‌شده:

```sh
docker compose exec backend python manage.py createsuperuser
```

توقف سرویس‌ها با حفظ داده:

```sh
docker compose down
```

پورت‌ها فقط روی loopback منتشر می‌شوند؛ PostgreSQL، Redis و RabbitMQ پورت عمومی ندارند. اگر پورت‌ها اشغال‌اند، `WEB_PORT` و `API_PORT` و `APP_BASE_URL` را در `.env` هماهنگ تغییر دهید. فایل `.env` توسط اسکریپت با کلیدهای تصادفی و دسترسی 0600 ساخته می‌شود و هرگز بازنویسی نمی‌شود.

## مسیر کاربر

۱. موضوع را انتخاب می‌کند: تشکر و قدردانی، دلگرمی و تشویق، تبریک و شادی، بهداشت فردی، بهداشت دهان، آرامش و صدا یا فضای مشترک. موضوع پیش‌فرض قدردانی است؛ پیام مثبت نیز همان قواعد محتوا، سقف ارسال و حق توقف دریافت را دارد.

۲. متن اولیه را می‌نویسد و متن نهایی بررسی‌شده را پیش از سفارش می‌بیند.

۳. شمارهٔ گیرنده را وارد و شمارهٔ خودش را با کد یک‌بارمصرف تأیید می‌کند. کد در حالت آزمایشی داخل رابط نمایش داده می‌شود.

۴. مبلغ سرور را می‌بیند و پرداخت آزمایشی انجام می‌دهد. سفارش در PostgreSQL ثبت و با RabbitMQ/Celery شبیه‌سازی می‌شود.

۵. سابقهٔ سفارش خودش را با شمارهٔ پوشیده می‌بیند. وضعیت «شبیه‌سازی‌شده» به معنی ارسال واقعی یا خوانده‌شدن نیست.

گیرنده می‌تواند با تأیید شمارهٔ خودش در صفحهٔ تنظیمات، دریافت را متوقف کند. پاسخ مستقیم، چت، افشای فرستنده و ارسال انبوه سازمانی در نسخهٔ اولیه وجود ندارند.

## انتخاب فنی

| بخش | انتخاب | دلیل |
| --- | --- | --- |
| رابط | Next.js، TypeScript، RTL و فونت محلی وزیرمتن | وب و موبایل با یک رابط واکنش‌گرا |
| بک‌اند | Django 5.2 LTS | پنل مدیریت آماده، تراکنش، احراز هویت و سرعت توسعه |
| داده | PostgreSQL 17 | مرجع سفارش، پرداخت، محدودیت‌ها و outbox |
| کش | Redis 7.4 | محدودیت نرخ و دادهٔ موقت؛ مرجع پرداخت نیست |
| صف | RabbitMQ 4.4 و Celery | جداسازی پردازش پیام از درخواست وب |
| اجرا | Docker Compose | محیط محلی یکسان و تست کامل سرویس‌ها |

هدف اولیه حدود ۱۰۰۰ کاربر ثبت‌شده با فعالیت کم است؛ ادعای پشتیبانی از ۱۰۰۰ درخواست هم‌زمان نداریم. اندازهٔ سرور پس از تست بار و اندازه‌گیری صف تعیین می‌شود. جزئیات تصمیم‌ها در [معماری](docs/architecture.md) آمده است.

## بررسی کیفیت

```sh
# تست بک‌اند در کانتینر، با پایگاه آزمایشی
docker compose run --rm -e DJANGO_TESTING=1 -e REDIS_URL=redis://redis:6379/15 backend python manage.py test --noinput

# بررسی رابط
cd frontend
npm ci
npm test
npm run typecheck
npm run build
```

تست دود از طریق پروکسی Next.js، نشست و CSRF، ورود، پیش‌نمایش، سفارش بدون تکرار، پرداخت آزمایشی، worker، سابقه و توقف دریافت را بررسی می‌کند. فقط آدرس loopback را می‌پذیرد و پیش از هر اقدام، آزمایشی‌بودن سرور را کنترل می‌کند.

CI روی GitHub تست بک‌اند با PostgreSQL، بررسی و build فرانت و اجرای Compose همراه تست دود را انجام می‌دهد. گردش‌کار اجرای محلی فقط با `workflow_dispatch` روی شاخهٔ `main` و runner مورد اعتماد با برچسب `begamnagam-local` اجرا می‌شود؛ به ابر آروان وابسته نیست. این فایل‌ها آماده‌اند؛ فعال‌شدن آن‌ها نیازمند قرارگرفتن کد روی GitHub و تنظیم runner است.

## مرز نسخهٔ فعلی

این نسخه برای بررسی محصول و تست محلی ساخته شده است. اتصال واقعی پنل پیامک، ارسال OTP واقعی، درگاه پرداخت و تأیید سمت سرور، بازگشت وجه، گزارش سوءاستفاده و عملیات پشتیبانی، سیاست نگهداری داده، پایش و آزمون بار باید پیش از عرضهٔ عمومی تکمیل شوند. در حالت غیرآزمایشی، آداپتورهای پرداخت و پیامک فعلاً غیرفعال می‌مانند؛ تغییر یک متغیر محیطی ارسال واقعی را فعال نمی‌کند.

قیمت ۲٬۰۰۰ تومان در Compose یک عدد آزمایشی قابل تغییر است و نرخ سرویس‌دهنده یا قیمت نهایی محصول نیست. جزئیات بیشتر و کارهای آینده در مستندات فازبندی ثبت شده‌اند.
