# بگم نگم

یک بازخورد کوچک، با احترام بیشتر. وب‌اپ فارسی برای فرستادن یادآوری‌های محترمانه یا قدردانی از طریق پیامک، بدون نمایش هویت فرستنده به گیرنده و بدون ایجاد گفت‌وگوی مستقیم.

این مخزن نسخهٔ محلی و آزمایشی محصول است. در تنظیمات پیش‌فرض، پرداخت، کد ورود و تحویل پیامک شبیه‌سازی می‌شوند. نسخه۰٫۸٫۳ امکان فعال‌سازی مستقل OTP واقعی برای تست شمارهٔ مجاز را دارد؛ پرداخت و پیام به گیرنده همچنان آزمایشی می‌مانند. حالت پیش‌فرض، متن آمادهٔ بررسی‌شده است؛ با تنظیم Ollama، مدل محلی متن مناسب را از بین نمونه‌های بررسی‌شده انتخاب می‌کند. ادعای ناشناسی مطلق یا تضمین ناراحت‌نشدن گیرنده نداریم.

## وضعیت فعلی پیاده‌سازی

نسخه۰٫۸٫۱۳ لینک لغو پیامک را به `begamnagam.ir/r#A7k2P9xQ` کوتاه می‌کند: بدون پیشوند scheme و با۸حرف/عدد تصادفی و یکتا. لینک‌های قبلی معتبر می‌مانند؛ محدودیت تلاش، CSRF و HTTPS حفظ شده‌اند. فقط پیش‌نمایش تازه قالب کوتاه را می‌گیرد. [گزارش و بررسی](docs/release-v0.8.13/README.fa.md) جزئیات را دارد.

نسخه۰٫۸٫۱۲ دو تیک مستقل در صفحهٔ هر حسابِ مدیریت اضافه می‌کند: «ارسال نامحدود برای تست» فقط در محیط demo و «لحن صریح‌تر و محترمانه» برای پیام‌های خروجی همان فرستنده. هر تغییر مجوز مستقل، دلیل و سابقه دارد؛ قطع دریافت، OTP، هدیه۳ارسال و ایمنی پیام حفظ می‌شوند. [روش استفاده](docs/operations.md#تنظیم-ارسال-و-لحن-هر-حساب-از-نسخه۰۸۱۲) و [گزارش بررسی و استقرار CT](docs/release-v0.8.12/README.fa.md) آماده‌اند.

نسخهٔ زیرساخت۰٫۸٫۱۱، Traefik را جای Caddy روی CT قرار می‌دهد. دامنه از مسیر Nginx داخلی با TLS معتبر، HTML و assetهای کامل برمی‌گرداند و HTTPS مستقیم IP حفظ شده است. دسترسی معمول از IP عمومی در این شبکه Connection refused می‌دهد؛ بررسی مسیر عمومی و مرورگر هنوز باز است. [گزارش و روش بازگشت](docs/domain-routing.fa.md) و [شواهد۰٫۸٫۱۱](docs/deployments/ct115-0.8.11-traefik.json) نتیجه‌های دقیق را دارند. فرانت۰٫۸٫۱۰ و سرویس‌های داده بدون recreate حفظ شدند.

نسخه۰٫۸٫۱۰ روی CT داخلی در [192.168.1.123](https://192.168.1.123) با HTTPS مستقر است. پرداخت و پیام به گیرنده آزمایشی‌اند؛ OTP واقعی فقط برای فهرست مجاز قبلی با بودجهٔ محدود حفظ شده است. [راهنمای استقرار داخلی](docs/deployment-internal.fa.md) و [گزارش بررسی](docs/deployments/ct115-0.8.10.json) جزئیات را دارند. دستگاه‌های تست باید CA داخلی را اعتماد کنند؛ نصب PWA روی گوشی در بررسی انسانی باقی است.

نسخه۰٫۸٫۹ به هر شمارهٔ تأییدشده، یک‌بار۳ارسال رایگان می‌دهد؛ حساب‌های موجود هم این هدیه را می‌گیرند. پیش‌نمایش رایگان سهمیه مصرف نمی‌کند؛ ثبت سفارش یک واحد رزرو می‌کند و شکست قطعی یا انقضای سفارش آن را یک‌بار برمی‌گرداند. ارسال چهارم با قیمت معمول است. سهمیه در فرم و سابقه نمایش داده می‌شود؛ محدودیت‌های روزانه، قطع دریافت و حالت آزمایشی برقرارند.

نسخه۰٫۸٫۸ فاصلهٔ هر جفت فرستنده/گیرنده و فاصلهٔ سراسری گیرنده را ۲۴ ساعت و سقف فرستنده را ۵ سفارش در ۲۴ ساعت می‌کند. در پنل حساب‌ها، ابزار «ریست محدودیت آزمایشی» با مجوز مستقل و ثبت سابقه اضافه شده است؛ [روش استفاده](docs/operations.md#ریست-محدودیت-برای-تست-ادمین) را ببینید.

نسخه۰٫۸٫۷ کادر توضیح آزمایشی را از مرور نهایی حذف می‌کند؛ عنوان دکمهٔ ارسال همچنان آزمایشی است.

نسخه۰٫۸٫۶ فرم را به نوشتن و یک صفحهٔ مشترک گیرنده/متن نهایی تبدیل می‌کند. نکته‌های نوشتن در هشدار زیر کادر هستند و شمارنده حفظ شده است؛ نوار انتخاب متن آماده و توضیح تکراری گیرنده حذف شده‌اند. تغییر شماره، پیش‌نمایش و تأیید قبلی را باطل می‌کند. [گزارش و تصاویر۰٫۸٫۶](docs/release-v0.8.6/README.fa.md) نتیجهٔ بررسی را دارد.

نسخه۰٫۸٫۵ فرم را سه‌مرحله‌ای می‌کند: نوشتن، گیرنده، و متن نهایی همراه تأیید و ارسال. نشان تأیید فرستنده از فرم گیرنده حذف شده و ورودی‌های شماره/OTP ارقام فارسی و عربی را هنگام ورود به انگلیسی تبدیل می‌کنند. [گزارش رابط۰٫۸٫۵](docs/release-v0.8.5/README.fa.md) تست موبایل، تلاش دوباره و تصاویر نمونه را دارد.

نسخه۰٫۸٫۴ خطای گواهی HTTPS در پایتون نیتیو را با CA معتبر سیستم رفع می‌کند؛ خطای قطعی دیگر موفقیت ساختگی برنمی‌گرداند و پاسخ نامعلوم در رابط مشخص است. ۹۹ تست بک‌اند و۱۳ تست فرانت موفق‌اند. در یک تست مجاز واقعی، کاوه‌نگار درخواست OTP را پذیرفت و کاربر ورود با کد را در مرورگر تکمیل کرد. این بررسی یک شماره، جای پایلوت داوطلبان یا پذیرش همهٔ گوشی‌ها نیست؛ پرداخت و پیام به گیرنده همچنان آزمایشی‌اند.

نسخه۰٫۸٫۳ تست محلی OTP واقعی با کاوه‌نگار را با مجوز صریح، فهرست هش شماره‌های مجاز، سقف روزانه و رزرو هر درخواست اضافه می‌کند. شبکه عمومی providerها خاموش می‌ماند و این استثنا فقط برای کد ورود ثابت است. ۹۶ تست بک‌اند و۱۳ تست فرانت موفق‌اند. برای تنظیم و خاموش‌کردن تست، [راهنمای OTP محلی](docs/operations.md#تست-محلی-otp-واقعی-با-پرداخت-و-پیام-آزمایشی) را ببینید؛ دریافت روی گوشی هنوز باید توسط صاحب شماره بررسی شود.

رابط پایه در نسخه۰٫۸٫۰ اضافه شد: معرفی تمام‌صفحه، فرم در صفحهٔ بعد، حرکت با «بعدی/قبلی»، درج مستقیم متن با انتخاب موضوع، حذف هدر/نوار بالای خانه و فوتر مخفی در موبایل. [گزارش رابط۰٫۸](docs/release-v0.8/README.fa.md) شواهد این اصلاحات را دارد. خروجی فازها و پذیرش‌های باز در بسته۰٫۷ محفوظ‌اند.

نسخه۰٫۷٫۰ خروجی نرم‌افزاری و آزمون‌های محلی فازهای۰تا۶ را تحویل می‌دهد. ۸۶ تست بک‌اند،۱۳ تست فرانت،۱۲ سناریوی پایلوت مصنوعی، آزمون بار۱۰۰۰حساب/۲۴۰۰درخواست، بازیابی رمز‌شده و بازگشت از candidate خراب ثبت شده‌اند. [گزارش نهایی](docs/release-v0.7/README.fa.md)، [شواهد](docs/release-v0.7/EVIDENCE.json)، [پوشش۵۶نیازمندی](docs/release-v0.7/TRACEABILITY.fa.md) و [چک‌لیست انسانی](docs/release-v0.7/HUMAN-REVIEW.fa.md) مرجع جاری‌اند.

تست‌های انسانی به دستور کارفرما نگه داشته شده‌اند. پذیرش رسمی G2/G3/G5/G6 و انتشار عمومی باز است؛ نتیجهٔ مصنوعی جای گوشی واقعی، داوطلبان یا پذیرش خارجی سرویس‌دهنده نیست. شبکه عمومی providerها پیش‌فرض خاموش است؛ استثنای تست OTP بالا انتشار عمومی نیست. هیچ push، جابه‌جایی وجه یا استقرار عمومی انجام نشده است؛ نسخهٔ داخلی CT جداگانه با مجوز کارفرما مستقر است. نسخه‌ها با commit محلی ثبت می‌شوند؛ [مجوز فازها](docs/release-v0.4/AUTHORIZATION.json) محفوظ است.

برای شبکه کند، کش اختیاری wheel رسمی: `python3 scripts/cache-crypto-wheel.py`؛ فایل‌ها با checksum رسمی بررسی و از Git حذف می‌شوند. Docker و CI از قفل کامل `backend/requirements.lock.txt` استفاده می‌کنند. محیط پاک و RabbitMQ4.4 نیز آزموده شده‌اند؛ [گزارش زیرساخت](docs/phase-two/INFRASTRUCTURE.md) روش تکرار را دارد.

## ویرایش UI با Hot Reload

برای کار روزمره روی UI، بک‌اند روی localhost:8000 فعال می‌ماند و فرانت با Fast Refresh اجرا می‌شود:

```sh
# فقط بار اول یا بعد از تغییر lockfile
cd frontend
npm ci
cd ..

# اجرای توسعه؛ هر ذخیرهٔ فایل بدون ساخت image اعمال می‌شود
make dev-ui
```

رابط توسعه روی [localhost:3000](http://localhost:3000) است. اگر فرانت Compose این پورت را گرفته است، فقط `docker compose stop frontend` را اجرا کنید؛ backend، worker و سرویس‌های داده فعال می‌مانند. برای تغییر متن، CSS یا کامپوننت، dev server را روشن نگه دارید؛ `make up` و build دوبارهٔ image لازم نیست.

بررسی نصب، آفلاین و چرخه Service Worker به اجرای production جدا نیاز دارد؛ dev برای بازبینی سریع UI است. نسخه۰٫۳٫۲ این گردش‌کار را اضافه می‌کند؛ شواهد انتشار۰٫۳٫۱ در بسته فاز دو تاریخی‌اند.

## اجرای کامل demo و بررسی PWA

پیش‌نیاز: Docker با Compose جدید، Python 3 برای ساخت تنظیمات و تست دود. استفاده از `make` اختیاری است.

```sh
python3 scripts/init-local.py
docker compose up --build -d --wait --wait-timeout 300
python3 scripts/smoke.py
```

- محصول: <http://localhost:3000>
- پنل مدیریت: <http://localhost:3000/admin/>
- سلامت بک‌اند: <http://localhost:8000/healthz>

ساخت مدیر بدون حساب یا رمز از پیش تعیین‌شده:

```sh
docker compose exec backend python manage.py createsuperuser
```

توقف سرویس‌ها با حفظ داده:

```sh
docker compose down
```

پورت‌ها فقط روی loopback منتشر می‌شوند؛ PostgreSQL، Redis و RabbitMQ پورت عمومی ندارند. اگر پورت‌ها اشغال‌اند، `WEB_PORT` و `API_PORT` و `APP_BASE_URL` را در `.env` هماهنگ تغییر دهید. فایل `.env` توسط اسکریپت با کلیدهای تصادفی و دسترسی 0600 ساخته می‌شود و هرگز بازنویسی نمی‌شود.

## کلید کاوه‌نگار

اتصال کاوه‌نگار برای کد ورود، ارسال پیامک و استعلام وضعیت پیاده شده است. تنظیمات آن در `.env` ریشه و `.env.example` وجود دارند:

```dotenv
KAVENEGAR_API_KEY=
KAVENEGAR_SENDER=
KAVENEGAR_OTP_MODE=sms
KAVENEGAR_OTP_TEMPLATE=
```

کلید پنل را در `KAVENEGAR_API_KEY` و شماره خط ارسال را در `KAVENEGAR_SENDER` وارد کنید. از نسخه۰٫۸٫۲، OTP با ارسال عادی `sms/send` و متن ثابت کد ورود فرستاده می‌شود؛ `KAVENEGAR_OTP_MODE=sms` است و الگو لازم نیست. بعداً برای استفاده از `verify/lookup`، حالت را به `lookup` تغییر دهید و نام الگوی تأییدشدهٔ ورود را در `KAVENEGAR_OTP_TEMPLATE` بگذارید. این مقادیر فقط به بک‌اند و پردازشگرها منتقل می‌شوند؛ آن‌ها را در متغیرهای `NEXT_PUBLIC_*` قرار ندهید. فایل `.env` خصوصی و خارج از Git است.

واردکردن کلید به‌تنهایی ارسال واقعی را فعال نمی‌کند؛ Compose محلی همچنان demo است. تست مستقل OTP به `OTP_BACKEND=kavenegar`، `LOCAL_REAL_OTP_ENABLED=1`، `OTP_TEST_RECIPIENT_HASHES` و سقف‌های مثبت `PROVIDER_DAILY_BUDGET_RIAL` / `OTP_MAX_COST_RIAL` نیاز دارد. نمونه‌ها این استثنا را خاموش نگه می‌دارند؛ تنظیم خصوصی تست در `.env` خارج از Git است. Django در اجرای مستقیم، فایل `.env` را خودکار نمی‌خواند و تنظیمات باید به محیط پردازش وارد شوند. برای تنظیمات انتشار، نمونهٔ `deploy/release.env.example` و [راهنمای اجرا](docs/operations.md) را ببینید. آزمون‌های خودکار با پاسخ‌های مصنوعی‌اند؛ دریافت واقعی باید روی گوشی بررسی شود.

## مسیر کاربر

۱. معرفی را می‌بیند، «بعدی» را می‌زند و شمارهٔ خودش را با OTP تأیید می‌کند. کد محلی برچسب آزمایشی دارد.

۲. یکی از هفت موضوع را می‌زند؛ متن نمونه مستقیم در کادر قرار می‌گیرد و قابل ویرایش است.

۳. در صفحهٔ بعد شماره گیرنده را وارد و متن کامل، لینک توقف دریافت، تعداد بخش و قیمت ثابت را در پیش‌نمایش بررسی می‌کند.

۴. در همان صفحهٔ متن نهایی، شماره و هزینه را می‌بیند، قوانین را تأیید می‌کند و ارسال را می‌زند؛ صفحهٔ تأیید دیگری وجود ندارد. محیط پیش‌فرض پرداخت و ارسال را شبیه‌سازی می‌کند؛ داده در PostgreSQL و صف RabbitMQ/Celery پردازش می‌شود. خطای پرداخت با تلاش دوباره روی همان سفارش ادامه پیدا می‌کند.

۵. رسید و سابقه با شماره پوشیده نمایش داده می‌شود. Back و دکمهٔ قبلی، متن همان مسیر را حفظ می‌کنند.

گیرنده با لینک امن داخل پیام، بدون حساب، دریافت را متوقف یا گزارش ثبت می‌کند؛ بازفعال‌سازی دریافت به OTP تازه شمارهٔ خودش نیاز دارد. پاسخ مستقیم، چت، افشای فرستنده و ارسال انبوه سازمانی در نسخهٔ اولیه وجود ندارند.

## انتخاب فنی

| بخش | انتخاب | دلیل |
| --- | --- | --- |
| رابط | Next.js، TypeScript، RTL و فونت محلی وزیرمتن | وب و موبایل با یک رابط واکنش‌گرا |
| بک‌اند | Django 5.2 LTS | پنل مدیریت آماده، تراکنش، احراز هویت و سرعت توسعه |
| داده | PostgreSQL 17 | مرجع سفارش، پرداخت، محدودیت‌ها و outbox |
| کش | Redis 7.4 | محدودیت نرخ و دادهٔ موقت؛ مرجع پرداخت نیست |
| صف | RabbitMQ 4.4 و Celery | جداسازی پردازش پیام از درخواست وب |
| اجرا | Docker Compose | محیط محلی یکسان و تست کامل سرویس‌ها |

هدف اولیه حدود ۱۰۰۰ کاربر ثبت‌شده با فعالیت کم است؛ ادعای پشتیبانی از ۱۰۰۰ درخواست هم‌زمان نداریم. آزمون محلیِ۲RPS برای۱۵دقیقه و جهش۱۰RPS برای۶۰ثانیه موفق شد؛ این نتیجه اندازهٔ سرور واقعی یا ظرفیت ارائه‌دهنده را تعیین نمی‌کند. جزئیات تصمیم‌ها در [معماری](docs/architecture.md) آمده است.

## بررسی کیفیت

```sh
# تست بک‌اند در کانتینر، با پایگاه آزمایشی
docker compose run --rm -e DJANGO_TESTING=1 -e REDIS_URL=redis://redis:6379/15 backend python manage.py test --noinput

# بررسی رابط
cd frontend
npm ci
npm test
npm run typecheck
npm run build
```

تست دود از طریق پروکسی Next.js، نشست و CSRF، ورود، پیش‌نمایش، سفارش بدون تکرار، پرداخت آزمایشی، worker، سابقه و توقف دریافت را بررسی می‌کند. فقط آدرس loopback را می‌پذیرد و پیش از هر اقدام، آزمایشی‌بودن سرور را کنترل می‌کند.

CI روی GitHub تست بک‌اند با PostgreSQL، بررسی و build فرانت و اجرای Compose همراه تست دود را انجام می‌دهد. گردش‌کار اجرای محلی فقط با `workflow_dispatch` روی شاخهٔ `main` و runner مورد اعتماد با برچسب `begamnagam-local` اجرا می‌شود؛ به ابر آروان وابسته نیست. این فایل‌ها آماده‌اند؛ فعال‌شدن آن‌ها نیازمند قرارگرفتن کد روی GitHub و تنظیم runner است.

## مرز نسخهٔ فعلی

این نسخه برای تست و بررسی محلی است. پروتکل اتصال‌ها و کنترل‌های عملیاتی پیاده شده‌اند، اما تأیید sandbox/زنده ارائه‌دهنده، بازپرداخت پس از تسویه، قراردادها، تعرفه/بودجه و مسئول پشتیبانی واقعی آماده نشده‌اند. فعال‌سازی خارجی به چند شرط صریح نیاز دارد؛ نتیجهٔ شبیه‌ساز محلی جای آزمون ارائه‌دهنده نیست. پذیرش انسانی و انتشار عمومی مستقل‌اند.

قیمت ۲٬۰۰۰ تومان در Compose یک عدد آزمایشی قابل تغییر است و نرخ سرویس‌دهنده یا قیمت نهایی محصول نیست. جزئیات بیشتر و کارهای آینده در مستندات فازبندی ثبت شده‌اند.
