# API فرانت و ربات تلگرام/بله — نسخهٔ دوم

قرارداد REST جدید روی `/api/v2` قرار دارد؛ API وب فعلی `/api/v1` حفظ می‌شود.
گردش کامل شامل OTP، پروفایل، اعتبار، دسته‌ها/نمونه‌ها، شمارهٔ مقصد، پیش‌نمایش
بررسی‌شده، رزرو اعتبار، تأیید ارسال، رسید/سوابق، بسته/کیف پول، دعوت، تنظیم
دریافت، پشتیبانی و درخواست حذف است.

نسخهٔ منتشرشدهٔ۰٫۱۹٫۰، نگهداری ماندگار هویت تلگرام/بله، chat_id، اتصال حساب پس از
OTP، بازیابی نشست و مرحلهٔ رمز‌شدهٔ مکالمه را اضافه می‌کند. پس از ری‌استارت،
adapter با کلید اختصاصی خود `POST /api/v2/bot/conversations/resolutions` را
می‌زند و cookie/CSRF، همان conversation و دستور ادامه را می‌گیرد. شش عملیات
تازهٔ Swagger، revision اتمیک، event_id تکرارپذیر و پاک‌سازی دادهٔ خصوصی دارند.
کلید از فرمان `manage_bot_integration` صادر می‌شود و توکن پیام‌رسان نیست.
روش provisioning، همهٔ endpointها، data مجاز، TTL، نمونهٔ کلاینت و مدیریت
انقضا/ارسال نامعلوم در بخش «گام۱» راهنمای کامل آمده است.
[شواهد استقرار۰٫۱۹٫۰](https://github.com/moein-tavakoli/begamnagam/releases/tag/v0.19.0) ثبت شده‌اند.

- [راهنمای کامل فارسی، قرارداد خطا و مراحل اتصال](../backend/core/api_v2/integration/guide.fa.md)
- [کلاینت پایتون مستقل از SDK پیام‌رسان](../backend/core/api_v2/integration/client.py)
- Swagger خصوصی: `/api/v2/document`
- OpenAPI خصوصی: `/api/v2/document/openapi.json`

اصلاح محلی۰٫۱۹٫۱: کلاینت HTTPS، Origin همان مبدأ API را همراه CSRF می‌فرستد.
راهنمای کامل، تنظیم نود HTTP Request در n8n، مسیر body توکن با headers/status
و انتقال درست cookieها را دارد. اجرای n8n روی لوکال برای اتصال به API سایت
مجاز است؛ افزودن Origin آدرس API لازم است و CORS عمومی فعال نمی‌شود.
این اصلاح هنوز انتشار تازهٔ سرور نیست؛ تنظیم هدر n8n با سرور۰٫۱۹٫۰ هم کار می‌کند.

اصلاح محلی۰٫۱۹٫۲، راهنمای تأیید OTP در n8n: پیام `invalid_otp` می‌تواند از sessionid
گم‌شده/عوض‌شده یا چالش مصرف‌شده باشد؛ صرف پیام «منقضی‌شده» علت را قطعی
نمی‌کند. راهنمای کامل، مسیر `/auth/sessions`، حفظ jar/challenge بین دو
execution، تفاوت مهلت OTP و نشست و ذخیرهٔ cookie چرخیدهٔ ورود را توضیح می‌دهد.
نیاز تأیید به cookie نشست ناشناس در OpenAPI روشن شده است؛ این اصلاح محلی
هنوز استقرار تازه‌ای ندارد و منطق یا مهلت OTP را تغییر نمی‌دهد.

`API_DOCUMENTATION_ENABLED=1` و نشست حساب فعال دارای مجوز
`core.view_api_documentation` هر دو لازم‌اند. ورود اختصاصی در
`/api/v2/document/login` است؛ حساب فرانت‌کار فقط همین مجوز را با staff و
superuser خاموش دارد. حالت پیش‌فرض و فایل‌های فرد غیرمجاز404می‌گیرند؛ ورودی
Swagger به فرم ورود هدایت می‌شود. تمام assetها و راهنما هم محافظت‌شده‌اند.
پس از تحویل، با مقدار0
مستندات HTTP بسته می‌شوند. فعال‌کردن مستندات، هیچ مجوز محصولی، provider،
هزینه، webhook ربات یا استقرار ایجاد نمی‌کند.

اتصال زندهٔ تلگرام/بله جدا از انتشار API است. شواهد فعلی سرور در
[انتشار۰٫۱۹٫۰](https://github.com/moein-tavakoli/begamnagam/releases/tag/v0.19.0) ثبت شده‌اند.
