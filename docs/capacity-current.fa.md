# برآورد ظرفیت — ۲۷ اکتبر ۲۰۲۶

## ظرفیت اندازه‌گیری‌شده پس از بهینه‌سازی

بهینه‌سازی ظرفیت روی CT و Nginx مرکزی فعال شد: Traefik۵۱۲MiB، شش فرانت و اتصال پایدار upstream. مسیر HTTPS دامنه با۷۵۰درخواست خواندن/ثانیه برای۳۰دقیقه، 1,350,000پاسخ، خطا/افت صفر وp95=27.278ms تأیید شد؛۱۳سرویس سالم و داده/هزینه حفظ شدند. [گزارش نهایی و حدود این سنجش](performance-2026-10-28/optimized.fa.md). پیشنهاد شروع عملیات۶۰۰RPS برای همین mix با۲۰٪حاشیه نسبت به نرخ آزموده‌شده است؛ WAN/ورود/ارسال/AI جدا هستند.

## سنجش اولیهٔ۲۸اکتبر، پیش از بهینه‌سازی

[تست دود، بار و فشار روی CT واقعی۰٫۱۱٫۰](performance-2026-10-28/README.fa.md) انجام شد. محیط اکنون۱۲CPUمنطقی و۲۴٬۰۰۰MiB RAM نشان می‌دهد. در تست مستقیم برنامه،۱۵۰درخواست خواندن/ثانیه برای۳۰ثانیه بدون خطا یا افت و باp95حدود۴۱ms گذشت؛ در۲۲۵افت ورودها۰٫۴۴٪ و در هدف۳۲۵با سقف۳۲درخواست درحال اجرا، افت۲۴٫۸۶٪شد. API عمومی خواندن تا۲۵۰RPS باp95حدود۲٫۶ms بدون خطا/افت گذشت. این اعداد سنجش خواندن کوتاه‌اند و به کاربران هم‌زمان، OTP، SMS یا AI تبدیل مستقیم نمی‌شوند.

در مسیر واقعی دامنه از Nginx مرکزی، مرحله۶۰RPS پس ازحدود۸ثانیه باعبور working set پراکسی از۹۰٪ سقف۶۴MiB متوقف شد. خطای HTTPغیرمنتظره، restart و OOM رخ نداد؛ ظرفیت پایدار کل دامنه هنوز از این تست کوتاه قابل اعلام نیست. منابع تازهٔ میزبان، سقف کانتینرها و تعداد پردازش‌ها را خودکار افزایش نداده‌اند. گزارش، CSV و JSON کامل در لینک بالا هستند؛ هیچ تنظیم سرور یا بودجه‌ای در این آزمون تغییر نکرد و provider فراخوانی نشد.

## برآورد برنامه‌ریزی قبلی، قبل از تغییر منابع

به‌روزرسانی منابع: کارفرما منابع را به **۱۲ CPU و۲۴گیگابایت RAM** افزایش داد؛ در بررسی زندهٔ این کار، `nproc=12` و `free` حدود۲۴۰۰۰MiB حافظه تأیید کردند. محاسبات زیر مربوط به پیکربندی پیشین‌اند و ظرفیت جدید یا سرعت AI را اثبات نمی‌کنند. [طرح و ارزیابی Ollama](ai-ollama.fa.md) جداگانه ثبت می‌شود.

کارفرما منابع فعلی را **۲ CPU، هشت گیگابایت RAM و اینترنت ۵۰Mbps** اعلام کرده است. خواندن زندهٔ سرور با SSH در این نشست timeout شد؛ منابع و سرعت آپلود مستقلاً اندازه‌گیری نشده‌اند. این سند برآورد برنامه‌ریزی است و نتیجهٔ تست بار محصول واقعی محسوب نمی‌شود.

در پیکربندی ثبت‌شدهٔ `compose.internal.yaml`، API یک worker و دو thread، پردازشگر پیامک یک worker از نوع solo، PostgreSQL حداکثر۲۰اتصال و frontend یک پردازش Node دارد. حافظهٔ کانتینرها نیز جداگانه محدود است: backend۱۹۲MiB، frontend۲۵۶MiB و PostgreSQL۱۲۸MiB. افزایش RAM ماشین، این سقف‌ها یا تعداد threadها را خودکار افزایش نمی‌دهد.

برای شروع، **۵۰ کاربر فعال با استفادهٔ سبک** هدف محتاطانهٔ آزمون است؛ این عدد ظرفیت تضمین‌شده نیست. فرض نمونه: هر کاربر به‌طور متوسط یک درخواست API در۱۰ثانیه، یعنی۵درخواست بر ثانیه. اگر متوسط زمان خدمت API حدود۲۰۰ms باشد، این ترافیک به‌طور متوسط یک thread از دو thread را مشغول می‌کند. در همین مدل،۱۰۰کاربر به۱۰درخواست بر ثانیه و اشغال هر دو thread می‌رسد و برای جهش ترافیک جا نمی‌ماند. زمان واقعی سرور هنوز اندازه‌گیری نشده است؛ تغییر این فرض، نتیجه را تغییر می‌دهد.

«کاربر آنلاین»، «درخواست در حال پردازش» و «ورود هم‌زمان با OTP» معیارهای متفاوت‌اند. UI منتظر خواندن/نوشتن کاربر، thread اختصاصی API نگه نمی‌دارد؛ ولی درخواست OTP فعلی هم‌زمان با تماس شبکه به کاوه‌نگار thread را اشغال می‌کند. API در تنظیم فعلی دو درخواست را هم‌زمان پردازش می‌کند و بقیه منتظر می‌مانند. پیامک نهایی صف دارد و زمان آن به provider و استعلام وضعیت وابسته است. رسیدهای در انتظار نیز در مرورگر هر۲ثانیه API را poll می‌کنند؛۵۰رسیدِ در انتظار حدود۲۵درخواست بر ثانیه اضافه می‌کنند و مشمول فرض «استفادهٔ سبک» بالا نیستند. فعال‌شدن GapGPT هم زمان خدمت و هزینهٔ جدا دارد.

۵۰Mbps در صورت اختصاصی‌بودن **آپلود** سرور، حداکثر نظری۶٫۲۵MB در ثانیه است؛ سربار پروتکل و مصرف مشترک آن را کمتر می‌کنند. برای مثال اگر بارگیری کامل هر بازدید تازه۵۰۰KB باشد، سقف نظری شبکه حدود۱۲٫۵بازدید تازه در ثانیه است؛ این اندازهٔ صفحه یک فرض است. مرورگر دارای کش، الگوی متفاوتی دارد.

آزمون قدیمی [BENCHMARK.json](release-v0.7/BENCHMARK.json) روی مک هشت‌هسته‌ای با۴thread وب،۱۰۰۰حساب ثبت‌شده و۱۰نشست فعال انجام شده است:۲درخواست بر ثانیه برای۱۵دقیقه و۱۰درخواست بر ثانیه برای۱دقیقه بدون خطا. p95 مرحلهٔ جهش۲۱۲ms بوده است. این آزمون ظرفیت سرور کنونی، هزار کاربر هم‌زمان، SMS واقعی یا GapGPT را اثبات نمی‌کند.

با منابع اعلام‌شده، هدف بعدی بررسی **۱۰۰ تا۲۰۰کاربر فعال سبک پس از تنظیم منابع کانتینر و workerها** است؛ هنوز نتیجهٔ اندازه‌گیری نیست. پیش از وعدهٔ ظرفیت، یک آزمون مرحله‌ای روی محیط هم‌اندازهٔ سرور با سناریوهای خواندن، ورود و ارسال/استعلام لازم است؛ نرخ خطا، p95، CPU، RAM، اتصال PostgreSQL و عمر صف باید همراه نرخ درخواست گزارش شوند. جهش OTP با تماس پولی provider بدون مجوز جداگانه اجرا نشده است. سرور و پیکربندی انتشار در این کار تغییر نکردند.
