# بهینه‌سازی برای جست‌وجو و پاسخ‌های هوش مصنوعی

تاریخ: ۲۰۲۶-۱۰-۲۸. این تغییرات در **نسخهٔ۰٫۱۳٫۰ منتشر شدند**.۱۰۳بررسی HTTP روی دامنه از Nginx مرکزی با TLS معتبر موفق بود؛ مسیر اینترنت عمومی از محیط اپراتور/ابزار وب در دسترس نبود. Search Console و حساب‌های بیرونی در این نوبت تغییر نکردند. [شواهد انتشار](deployments/ct115-0.13.0.json).

## سیاست انتخاب‌شده

کارفرما انتخاب کرد: «جست‌وجو و پاسخ AI مجاز؛ آموزش مسدود». این سیاست در `robots.txt` برای عامل‌های شناخته‌شده بیان می‌شود؛ جای احراز هویت یا کنترل استفادهٔ همهٔ شرکت‌ها از متن عمومی را نمی‌گیرد. برای قابلیت‌های AI گوگل نیز اصول SEO، محتوای قابل خواندن، ایندکس و snippet مجاز لازم‌اند؛ متاتگ یا schema اختصاصی GEO وجود ندارد. این کار تضمین رتبه یا استناد نیست.

## محتوا و هویت برند

- `/about` معرفی کوتاه سرویس، مخاطب شماره‌های ایران، حدود ناشناس‌بودن، اختیار گیرنده، بررسی متن، تفاوت ارسال با خواندن و نحوهٔ اعتبار را در HTML سمت سرور نمایش می‌دهد.
- واقعیت‌های پایدار صفحهٔ معرفی و فایل متنی از یک منبع مشترک در `frontend/lib/seo.ts` می‌آیند و به bootstrap، ورود یا JavaScript نیاز ندارند.
- راهنما مراحل تأیید شماره، نوشتن، بررسی گیرنده/متن و تأیید ارسال را دارد. پرسش تعریف سرویس اضافه شد؛ پاسخ‌های FAQ پیوند ثابت مانند `/help#about-service-answer` دارند.
- سهمیه‌ها و فاصله‌های قابل‌تغییر دعوت از پاسخ ثابت حذف شدند. قابلیت بازنویسی با وضعیت قابل مشاهدهٔ فرم توضیح داده می‌شود و به نام یک ارائه‌دهنده محدود نیست.
- `/about` با `AboutPage` به همان `Organization` و `WebSite` متصل است؛ breadcrumb، canonical، متادیتای اشتراک‌گذاری، لینک پایین صفحات و sitemap آن نیز اضافه شدند. FAQ همچنان از متن قابل مشاهده ساخته می‌شود.
- شش صفحهٔ عمومی `/`، `/help`، `/privacy`، `/links`، `/pricing` و `/about` بررسی شدند. نام حقوقی، نشانی، تلفن، ایمیل، امتیاز، آمار مشتری، تاریخ انتشار یا مالکیت شبکهٔ اجتماعی تأییدنشده ساخته نشد. قیمت/Offer ثابت هم اضافه نشد؛ قیمت و روش‌های فعال از تنظیمات جاری می‌آیند.

## خزنده‌ها

| عامل یا توکن | انتشار با `SEO_INDEXABLE=1` | محیط بدون ایندکس |
| --- | --- | --- |
| `OAI-SearchBot`, `ChatGPT-User` | عمومی مجاز؛ خصوصی مستثنا | `Disallow: /` |
| `Claude-SearchBot`, `Claude-User` | عمومی مجاز؛ خصوصی مستثنا | `Disallow: /` |
| `PerplexityBot`, `Perplexity-User` | عمومی مجاز؛ خصوصی مستثنا | `Disallow: /` |
| `GPTBot`, `ClaudeBot` | `Disallow: /` | `Disallow: /` |
| `Google-Extended`, `Applebot-Extended` | استفادهٔ آموزشی مسدود | استفادهٔ آموزشی مسدود |
| `CCBot` | جمع‌آوری برای مجموعه‌داده مسدود | جمع‌آوری مسدود |
| Googlebot، Bingbot و Applebot | قواعد عمومی موجود و `noindex` خصوصی | قواعد عمومی موجود تا خواندن `noindex` ممکن بماند |

`Google-Extended` هم آموزش و هم grounding بعضی محصولات Gemini را کنترل می‌کند و این دو کاربرد در آن قابل تفکیک نیستند. منع آموزش ممکن است آن پاسخ‌های Gemini را نیز محدود کند؛ Google Search و AI Overviews با Googlebot کنترل می‌شوند و بسته نشده‌اند. `Applebot-Extended` نیز کنترل استفاده است، نه یک خزندهٔ HTTP مستقل.

مسیرهای حساب، سابقه، دعوت، ترجیحات، خرید/کیف پول، گیرنده، مدیریت، API و فایل آفلاین در گروه AI مستثنا هستند. `/r$`، `/r/` و `/r?` ترکیب شده‌اند تا گیرنده مستثنا باشد و `/robots.txt` اشتباهاً زیر پیشوند `/r` مسدود نشود.

بعضی fetcherهای درخواستی مانند ChatGPT-User و Perplexity-User ممکن است robots را اعمال نکنند. نشست، مالکیت و کنترل‌های سرور همچنان از دادهٔ خصوصی حفاظت می‌کنند. هیچ اعتماد امنیتی، bypass یا استثنای محدودکننده براساس User-Agent اضافه نشد. User-Agent اثبات هویت ربات نیست؛ این قواعد هم محتوای قبلاً دریافت‌شده را پس نمی‌گیرند.

## فایل اختیاری llms.txt

`/llms.txt` فقط در build عمومی پاسخ۲۰۰ `text/plain; charset=utf-8` دارد: معرفی، واقعیت‌های مشترک و شش لینک عمومی canonical. URL حساب، API، گیرنده، query، cookie یا دادهٔ نشست در آن نیست. صفحات عمومی با هدر `Link` و رابطهٔ `describedby` آن را معرفی می‌کنند.

این فایل کمکی خودش `X-Robots-Tag: noindex` دارد؛ لینک‌هایش `nofollow` نیستند و جایگزین HTML یا sitemap نیست. در محیط بدون ایندکس، پاسخ۴۰۴، `no-store` و `noindex, nofollow` دارد. route آن از CSP مخصوص HTML مستثناست و دادهٔ درخواست/کاربر نمی‌خواند. llms.txt یک پیشنهاد عمومی است و عامل رتبه‌بندی گوگل نیست.

## شواهد

- ۶۰آزمون فرانت، TypeScript و build جداگانهٔ production موفق‌اند. ساخت با مبدأ `https://begamnagam.ir` و ایندکس فعال انجام شد؛ dev server اصلی با Fast Refresh روشن ماند.
- checker در HTTPS توسعه و build عمومی هرکدام۱۰۳درخواست موفق داشت: شش صفحهٔ عمومی، هفت عامل اشتراک‌گذاری، شش عامل AI، هشت صفحهٔ خصوصی و فایل‌های عمومی.
- متن اصلی و JSON-LD برای تمام عامل‌های آزموده‌شده یکسان بودند. گراف، canonical، sitemap، robots، متاتگ اینماد و پاسخ llms.txt بررسی شدند؛ محتوای پنهان یا ویژهٔ AI ساخته نشد.
- معرفی و راهنما در Chromium156.0.8078.48 با عرض۳۷۵ و۱۴۴۰، JavaScript روشن/خاموش و API خارج از دسترس قابل خواندن بودند؛ سرریز افقی یا خطای مرورگر نداشتند. لینک مراحل و بازشدن پاسخ FAQ نیز آزموده شدند.
- در این کار شماره، OTP، سفارش، پرداخت یا پیامکی ایجاد نشد؛ دیتابیس، صف، Redis و provider تغییر نکردند. اجرای مرورگری فقط context تست مستقل داشت.

دادهٔ خام در `.local/geo-20261028/` نگه‌داری می‌شود و در Git نیست. این بررسی شاهد حضور در نتایج واقعی سرویس‌های AI نیست.

## پیگیری بیرونی پس از انتشار

1. checker روی HTTPS دامنه از مسیر Nginx مرکزی موفق بود؛ دسترسی مستقل اینترنتی و WAF/CDN هنوز نیاز به بررسی دارند؛ حفاظت خصوصی را برای User-Agent ادعایی باز نکنید.
2. sitemap جدید و `/about` را در Google Search Console و Bing Webmaster بررسی کنید. خروجی build محلی شاهد ایندکس عمومی نیست.
3. برای پرسش‌های ثابت مانند «بگم نگم چیست؟»، «آیا گیرنده شمارهٔ فرستنده را می‌بیند؟» و «چطور دریافت را قطع کنم؟»، منبع استناد و صحت پاسخ AI را در زمان‌های مشخص ثبت کنید.
4. با تغییر هدیه، اعتبار، حریم خصوصی یا بازنویسی، متن عمومی و پاسخ‌های مشترک را هم بازبینی کنید. قیمت زنده را به فایل ثابت AI کپی نکنید.
