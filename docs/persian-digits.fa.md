# نمایش فارسی اعداد و دادهٔ استاندارد — محلی روی dev

اعداد رابط اصلی، فرم‌ها، صفحه‌های عمومی، مدیریت Next.js و ادمین Django با
نسخهٔ رسمی **Vazirmatn Farsi-Digits 33.003** نمایش داده می‌شوند. این قلم شکل
هر ده رقم انگلیسی و عربی را فارسی رسم می‌کند؛ به متن، مقدار فیلد یا JSON
دست نمی‌زند. بنابراین شماره، OTP، مبلغ، تاریخ، شناسه، لینک، کپی شمارهٔ کارت و
امضای پیش‌نمایش با قالب قبلی و معتبر خود باقی می‌مانند.

ورودی‌های شماره/OTP و اطلاعات بانکی، رقم فارسی و عربی را همچنان مستقل در
بک‌اند به ASCII یکسان‌سازی می‌کنند؛ صفر اول حفظ می‌شود. مقدارهای عددی JSON
عدد هستند و فیلدهای عددی مدل عدد صحیح می‌مانند. شماره و اطلاعات بانکی پیش
از رمزنگاری با رقم انگلیسی استاندارد می‌شوند؛ OTP به‌صورت digest وابسته به
چالش نگهداری می‌شود. متن و snapshot تأییدشده برای تغییر ظاهر بازنویسی نمی‌شوند.

## یکسان‌سازی ورودی تازه — ۲۰۲۶-۱۰-۲۹

فیلدهای شماره و کد، مبلغ، تعداد، تنظیمات و تاریخ، ارقام فارسی و عربی را می‌پذیرند.
قلم همچنان شکل فارسی را نشان می‌دهد. ویرایشگر عددی به ورودی بومی number وابسته
نیست، چون بعضی مرورگرها رقم فارسی را پیش از رسیدن به برنامه حذف می‌کنند؛
اعتبارسنج بومی عدد/تاریخ برای required، کمینه، بیشینه و گام همچنان استفاده می‌شود.
جداکنندهٔ هزارگان و ممیز فارسی در فیلد عددی پذیرفته می‌شود؛ فیلد صحیح، اعشار را
رد می‌کند. تاریخ واریز همچنان میلادی با قالب سال-ماه-روز است و رقم فارسی/عربی
نیز می‌پذیرد. بازنشانی فرم محدودیت‌ها را از بین نمی‌برد.

هنگام ساخت درخواست، `api()` نسخه‌ای استاندارد از ورودی تازه می‌سازد: ارقام
رشته‌های قابل ورود به ASCII تبدیل می‌شوند و عدد/Boolean/null همان نوع JSON
خود را دارند. متن نمایشی و state فرم برای این ارسال بازنویسی نمی‌شوند.
عددهای داخل متن تازهٔ پشتیبانی، نام بسته و دلیل تغییر نیز پیش از ارسال استانداردند.

سرور مستقلاً در parser مشترک بدنهٔ JSON و فرم‌های ادمین همین تبدیل را **پیش
از اعتبارسنجی و ثبت** انجام می‌دهد؛ دورزدن جاوااسکریپت مانع آن نیست. سرور تمام
ارقام ده‌دهی Unicode را به ASCII تبدیل می‌کند. نوع صحیح JSON و اعتبارسنجی هر
فیلد لازم می‌ماند؛ برای مثال رشتهٔ عددی جای مقدار عددی JSON پذیرفته نمی‌شود.
کد و مرجع رشته‌ای، صفرهای ابتدایی را حفظ می‌کنند. در ادمین نیز تبدیل کلاینت و
سرور پیش از ذخیره برقرار است و فیلدهای چندمقداری فرم حفظ می‌شوند.

رمز، نام کاربری ورود، CSRF، شناسهٔ غیرشفاف، توکن، امضا، نسخهٔ قرارداد و authority
دادهٔ ماشینی هستند و عیناً حفظ می‌شوند. تبدیل ورودی تازه پیش از HMAC/امضا انجام
می‌شود؛ snapshot و سوابق قبلی یا محتوای مهرشده در مرحلهٔ ذخیره بازنویسی نمی‌شوند.
پاسخ سرویس‌دهنده، callback درگاه و بدنهٔ خام HTTP برای تبدیل ظاهر دستکاری نمی‌شوند.

۵۰۱ تست PostgreSQL، ۷۶ تست فرانت و TypeScript موفق‌اند و migration تازه وجود ندارد. بررسی مرورگر در
۳۷۵ و ۱۴۴۰، رقم فارسی/عربی، صفر ابتدا، مبلغ JSON عددی، مرز مقدار، اعشارِ نامعتبر،
بازنشانی، تاریخ نامعتبر/آینده، فرم ادمین و حفظ رمز را پوشش داد؛ ۳۰ بررسی موفق بود.
ذخیرهٔ واقعی در دیتابیس آزمون، برای متن پشتیبانی و digest آن، نام بسته و فرم
ادمین با ارقام انگلیسی بررسی شد. این آزمون‌ها در محیط مستقل‌اند و هیچ تراکنش
یا پیامک واقعی ایجاد نکردند. API واقعی لوکال پس از بارگذاری تغییر سالم است.

## محل قلم و مجوز

- فرانت: `frontend/public/fonts/vazirmatn-fd/`، با تعریف چهار وزن۴۰۰تا۷۰۰در
  `frontend/app/globals.css`. فیلدها فونت والد را ارث می‌برند و بخش‌های code/pre
  هم همین نمایش ارقام را دارند. هیچ CDN یا وابستگی نصب‌شدهٔ تازه لازم نیست.
- ادمین: `backend/core/static/admin/fonts/vazirmatn-fd/` و
  `backend/core/static/admin/css/persian-digits.css`، از قالب پایهٔ ادمین بار می‌شوند.
  مسیر `/static/admin/` با پراکسی موجود سازگار است؛ CSP همچنان فقط font محلی را
  می‌پذیرد. برای اجرا، collectstatic معمول انتشار لازم است.
- فایل‌های قلم بدون تغییر از tag رسمی دریافت شده‌اند. `source.json` در هر دو
  پوشه، نسخه، مبدأ و SHA256 فایل‌ها را دارد؛ `OFL.txt` مجوز همراه قلم است.

## OTP و حرکت فوکوس

glow با رنگ تم برنامه دور کادر فعال برقرار است و خط محیطی SVG هم‌زمان با
زمان‌بندی `ease-in-out` می‌چرخد. با جابه‌جایی مکان‌نما یا کلیک روی رقم، هر دو
به همان کادر منتقل می‌شوند. در کاهش حرکت، خط ثابت و حاشیهٔ واضح حفظ می‌شوند.
تغییر نمایش و حرکت، درخواست کد یا تأیید خودکار ایجاد نمی‌کند.

## اعتبارسنجی اولیهٔ قلم

۷۰تست فرانت و TypeScript موفق‌اند.۵۶تست PostgreSQL با دیتابیس مستقل و سرویس‌های
ساختگی موفق‌اند؛ شماره و کد فارسی/عربی، صفر ابتدایی، digest کد، شمارهٔ رمز‌شده
و مرجع بانکی با ذخیرهٔ انگلیسی بررسی شدند. migration تازه وجود ندارد.

در مرورگر، تصویر هر رقم ASCII و عربی، پس از هم‌ترازکردن محدودهٔ جوهر، دقیقاً
با رقم فارسی یکسان بود. مقادیر DOM و درخواست OTP، مرجع دارای صفر اول، مبلغ
ورودی number و تاریخ ISO انگلیسی ماندند؛ اعتبارسنجی min/max ورودی بومی حفظ شد.
فونت ادمین و CSS از پراکسی واقعی پاسخ۲۰۰دادند. glow، منحنی حرکت خط و نبود خطای
JavaScript تأیید شدند. شواهد تست در `.local/otp-reference/` هستند و به نشست
واقعی کاربر تزریق نشده‌اند. OTP واقعی برای این بررسی درخواست نشد.
