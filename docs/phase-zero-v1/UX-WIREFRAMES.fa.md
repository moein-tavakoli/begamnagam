# وایرفریم مستندی Mobile-first

شناسه: BN-UX-001 | نسخه: ۱٫۰ | وضعیت: طرح بررسی؛ هیچ UI یا کد برنامه ساخته نشده

طراحی پایه از عرض ۳۲۰ CSS px، یک ستون و سپس افزایش عرض است. این جعبه‌ها ترتیب محتوا و رفتار را مشخص می‌کنند؛ طراحی گرافیکی نهایی، prototype اجرایی یا تأیید دسترس‌پذیری نیستند.

## W-01 — شروع و متن

```text
┌─────────────────────────────┐
│ بگم نگم       راهنما / ورود │
│ یک حرف محترمانه، یک حس بهتر │
│ [تشکر ✓] [تشویق] [تبریک]    │
│ [بهداشت] [آرامش] [فضای جمع] │
│ موضوع‌ها: هر هفت مورد مستقل │
│ توضیح اختیاری              │
│ [متن کوتاه…             ]  │
│ ۰ از ۲۸۰                   │
│ پیشنهاد متن از قالب مصوب    │
│ گیرنده هویت شما را نمی‌بیند │
│ [ادامه و پیش‌نمایش]         │
│ قواعد، حریم خصوصی، هزینه   │
└─────────────────────────────┘
```

قدردانی پیش‌فرض؛ موضوع بهداشت دهان و بدن جداست. برچسب demo و قیمت نمونه در محیط آزمایشی همیشه آشکار است. متن توضیح راه را روشن می‌کند، اما از placeholder به‌جای label استفاده نمی‌شود. هنگام ورود به OTP، متن فقط در state حافظه حفظ و ذخیره دائمی نمی‌شود.

## W-02 — ورود و شماره گیرنده

```text
┌─────────────────────────────┐
│ بازگشت             ورود    │
│ شماره خودتان               │
│ [09…                     ] │
│ [دریافت کد]                │
│ کد ۵ دقیقه اعتبار دارد     │
│ [کد تأیید               ]  │
│ [تأیید]   ارسال مجدد: ۶۰ث  │
│ سپس: شماره گیرنده          │
│ [09…                     ] │
│ فقط یک شماره؛ بدون مخاطبین │
│ [ساخت پیش‌نمایش نهایی]     │
└─────────────────────────────┘
```

فیلدها inputmode مناسب، paste و ارقام فارسی/عربی دارند. خطا کنار فیلد و خلاصه قابل focus، ارسال وضعیت با aria-live مناسب؛ کد در URL نیست. با keyboard باز، دکمه و خطا از viewport خارج نشوند. resend تا موعد مسدود است و text دکمه تغییر قابل فهم دارد.

## W-03 — پیش‌نمایش و تأیید خرید

```text
┌─────────────────────────────┐
│ بازبینی نهایی              │
│ گیرنده: 09•••••••12        │
│ «متن کامل مصوب…            │
│ بگم نگم؛ توقف و گزارش:      │
│ https://دامنه/لینک‌محدود»   │
│ پردازش: پیشنهاد قالب آماده │
│ بخش SMS: …  | انقضا: …     │
│ مبلغ: ۲۰۰۰ تومان — نمونه   │
│ قواعد شکست و بازپرداخت     │
│ □ متن و مبلغ را دیدم       │
│ [تأیید و پرداخت آزمایشی]   │
│ [اصلاح موضوع/گیرنده]       │
└─────────────────────────────┘
```

قیمت و متن در سرور ثابت‌اند؛ چک‌باکس از قبل انتخاب نشده. دکمه در pending غیرفعال و retry همان کلید را نگه می‌دارد. اگر quote منقضی شود، سفارش تازه پنهانی ساخته نمی‌شود. در محیط واقعی دکمه نام/مبلغ درست و دامنه درگاه شناخته‌شده دارد. شماره کامل پیش از تأیید فقط در فیلد ورودی خود کاربر قابل اصلاح است.

## W-04 — رسید و استعلام

```text
┌─────────────────────────────┐
│ وضعیت سفارش                │
│ پرداخت: در حال بررسی       │
│ ارسال: هنوز آغاز نشده       │
│ کد پیگیری: …               │
│ برای این سفارش دوباره نخرید │
│ [بررسی دوباره وضعیت]       │
│ [سابقه من]   [پشتیبانی]    │
└─────────────────────────────┘
```

وضعیت‌های مالی و ارسال جدا؛ پس از سقف polling دکمه استعلام دستی. صفحه از نتیجه callback حدس نمی‌زند. «تحویل آزمایشی» فقط demo است. جزئیات خصوصی گیرنده یا علت توقف او نمایش داده نمی‌شود. مسیر پشتیبانی درون برنامه/کانال رسمی سرویس است و به طرف مقابل وصل نمی‌کند.

## W-05 — صفحه گیرنده و تنظیمات

```text
┌─────────────────────────────┐
│ بگم نگم                    │
│ انتخاب شما درباره دریافت   │
│ [توقف همه پیام‌های سرویس]  │
│ [گزارش پیام نامناسب]       │
│ بدون حساب و بدون پاسخ دادن │
│ تأیید جدا → ثبت روی سرور   │
│ فعال‌سازی دوباره: OTP خود  │
└─────────────────────────────┘
```

در صفحه لینک، متن پیام/شماره/فرستنده نمایش داده نمی‌شود. اسکن خودکار لینک و بازشدن GET بی‌اثر است. گزارش دلیل ساختاری دارد و کد پیگیری می‌دهد. لینک نامعتبر/منقضی فقط راه تأیید شماره خود برای ترجیحات را نشان می‌دهد؛ اطلاعات دیگری افشا نمی‌کند.

## W-06 — آفلاین، نصب و update

| حالت | نمایش و رفتار پیشنهادی |
| --- | --- |
| آفلاین پس از بازدید | معرفی/راهنمای عمومی و «اینترنت قطع است؛ ورود، پرداخت و ارسال به اتصال نیاز دارند»؛ دکمه تلاش دوباره، بدون تاریخچه خصوصی |
| قطع وسط پرداخت | «نتیجه هنوز مشخص نیست؛ پس از اتصال وضعیت همین سفارش را بررسی کنید»؛ هیچ موفقیت یا سفارش دوم خودکار |
| قطع هنگام توقف دریافت | «ثبت نشد؛ برای ثبت توقف دوباره تلاش کنید»؛ موفقیت ساختگی/صف Background Sync نداریم |
| نصب Android | دعوت اختیاری در نقطه آرام فقط وقتی قابلیت پشتیبانی می‌شود؛ بستن دعوت محترم شمرده شود |
| نصب iOS | راهنمای افزودن به Home Screen متناسب با Safari؛ در standalone دعوت تکرار نشود |
| نسخه جدید آماده | پیام کوچک با انتخاب «بعداً» و «به‌روزرسانی در زمان مناسب»؛ وسط متن/OTP/درگاه reload تحمیلی ممنوع |
| خروج/حساب دیگر | متن/گیرنده/رسید خصوصی از حافظه پاک؛ Back/آفلاین داده حساب قبل را ندهد |

## ضوابط طراحی و آزمون بعدی

هدف لمسی پروژه حداقل ۴۴×۴۴، متن پایه پیشنهادی ۱۶px، فاصله کافی، focus واضح و کنتراست مطابق WCAG 2.2 AA است. هدف ۴۴px انتخاب پروژه است و با حداقل تمام معیارهای استاندارد یکسان معرفی نمی‌شود. همه معیارهای قابل اعمال AA بررسی می‌شوند؛ چند تست نمونه جای ارزیابی کامل را نمی‌گیرد.

عرض‌های ۳۲۰، ۳۶۰، ۳۷۵، ۳۹۰، ۴۱۲، ۷۶۸ و ۱۲۸۰، افقی، متن ۲۰۰٪/reflow، TalkBack/VoiceOver، keyboard، safe area و reduced motion جزو پذیرش‌اند. روی موبایل CTA تمام‌عرض؛ sticky فقط اگر focus/keyboard و محتوا را نپوشاند. desktop همان ترتیب معنا را حفظ می‌کند؛ فرم دوتایی یا انیمیشن اجباری لازم نیست.

ماتریس پیشنهادی مرورگر: Chrome Android و Safari iOS، دو نسخه عمده آخر در زمان هر gate، روی حداقل یک Android میان‌رده و یک iPhone واقعی در حالت browser و standalone؛ Chrome/Edge دسکتاپ، Safari و Firefox برای وب معمولی. شماره نسخه و مدل هنگام اجرا ثبت می‌شود؛ این سند ادعای تست فعلی روی هیچ دستگاهی ندارد.
