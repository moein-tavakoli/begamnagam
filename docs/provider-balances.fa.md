# اعتبار سرویس‌ها در بالای مدیریت — نسخهٔ۰٫۱۳٫۰

بالای `/manage` و زیر نوار عنوان، دو بخش اعتبار پیامک و GapGPT نمایش داده می‌شوند. این اطلاعات فقط برای مدیر فعال با مجوز موجود `core.view_operations` قابل خواندن‌اند. ادمین پشتیبانی بدون این مجوز به موجودی حساب سرویس‌دهنده دسترسی ندارد. این تغییر با نسخهٔ۰٫۱۳٫۰ روی سرور منتشر شد؛ استعلام واقعی کاوه‌نگار از خود سرور نیز موفق بود. [شواهد انتشار](deployments/ct115-0.13.0.json).

## کاوه‌نگار

[مستند رسمی Info](https://kavenegar.com/rest.html) مسیر `GET /v1/{API-KEY}/account/info.json` و فیلد عدد صحیح `entries.remaincredit` بر حسب **ریال** را معرفی می‌کند. همین مسیرِ فقط‌خواندنی با کلید خصوصی موجود استفاده می‌شود. مقدار پاسخ به شکل رشتهٔ صحیح در API داخلی برمی‌گردد؛ فرانت با BigInt به تومان تبدیل می‌کند و رقم دهمِ تومان را هم بدون گردکردن یا خطای ممیز شناور نگه می‌دارد. صفر واقعی با نتیجهٔ نامعلوم متفاوت است. مدل، پیامک، کد ورود، اعتبار هدیه و دفتر هزینه برای استعلام صدا زده یا تغییر داده نمی‌شوند.

استعلام واقعی در پروفایل واقعیِ فعلی لوکال موفق بود و مقدار معتبر ریالی دریافت شد؛ هیچ SMS یا تماس مدل انجام نشد. عدد حساب در فایل گزارش تست ثبت نشده؛ فقط وضعیت موفقیت و واحد ثبت شده‌اند.

## GapGPT

در منابع رسمی بررسی‌شده در۲۸اکتبر۲۰۲۶، قراردادِ مستند و قابل اتکا برای خواندن **موجودی کیف پول API با `GAPGPT_API_KEY`** تأیید نشد. [راهنمای رسمی شروع](https://gapgpt.app/platform-v2/docs/quickstart) و منابع عمومی خودِ برنامه بررسی شدند: کیف پول داخل پنل از دادهٔ حساب واردشده استفاده می‌کند، نه قراردادی مستند برای کلید مدل. سهمیهٔ یک API key هم به‌جای پول کیف حساب گزارش نمی‌شود.

بنابراین کارت GapGPT لینک [کیف پول رسمی API](https://gapgpt.app/platform-v2/wallet) را نشان می‌دهد و می‌گوید «API موجودی تأیید نشده». این به معنی نبودن قطعی چنین APIای نزد ارائه‌دهنده نیست. هیچ endpoint حدسی، ورود با OTP، توکن نشست وب یا scrape حساب خصوصی اضافه نشده است. اگر ارائه‌دهنده قرارداد رسمیِ موجودی با کلید را منتشر یا ارائه کند، همین بخش قابلیت افزودن adapter دارد؛ فعلاً مبلغ ساختگی یا صفر به‌جای موجودی نشان داده نمی‌شود. کیف پول GapCode با کیف پول API متفاوت است و لینک به کیف پول API می‌رود.

## تازگی، خطا و امنیت

- هر سرویس درخواست داخلی جدا دارد تا خرابی یکی بارگذاری دیگری یا کار با پنل را متوقف نکند. مرورگر فقط در تب قابل مشاهده و آنلاین خواندن را تکرار می‌کند؛ کلیدها و درخواست مستقیم سرویس‌دهنده وارد فرانت نمی‌شوند.
- پاسخ موفق۱۲۰ثانیه مشترک میان مدیران cache می‌شود؛ رابط زمان استعلام و تأخیر حداکثر معمول۲دقیقه را مشخص می‌کند. درخواست ناموفق۳۰ثانیه cache می‌شود و آخرین مشاهدهٔ موفق تا۳۰دقیقه برای حالت قدیمی باقی می‌ماند.
- هنگام شکست، آخرین مقدار فقط با برچسب «قدیمی»، زمان اصلی و توضیح شکست تازه نمایش داده می‌شود. بدون مشاهدهٔ معتبر، مقدار `null` است و «فعلاً دریافت نشد» نمایش داده می‌شود؛ صفر فرض نمی‌شود. دادهٔ این نوار مبنای افزایش/کاهش اعتبار یا فعال‌کردن سرویس نیست.
- قفل کوتاه cache جلوی تکثیر استعلام‌های هم‌زمان را می‌گیرد. namespace با HMAC کلید سرویس جداست تا پس از تعویض کلید، اعتبار حساب قبلی نمایش داده نشود. خرابی cache تماس خارجی را آغاز نمی‌کند.
- استعلام کاوه‌نگار فقط HTTPS روی میزبان ثابت و مسیر دقیق Info است؛ redirect پذیرفته نیست. مهلت۴ثانیه و سقف پاسخ۱۶KiB دارد. نوع JSON، کد موفقیت، شکل شیء و مقدار صحیح معتبر لازم‌اند؛ پاسخ خام، استثنای URLحاوی کلید و جزئیات حساب در log/API فرانت افشا نمی‌شوند.
- پروفایل demo/شبکهٔ خاموش، اعتبارنامهٔ خالی/نامعتبر یا میزبان تغییریافته تماس خارجی نمی‌سازد. پروفایل واقعی فعلی، محدودیت‌ها، ارسال واقعی OTP/SMS و کلیدهای خصوصی حفظ شده‌اند. هیچ متغیر env تازه یا تغییر کلید لازم نیست.

## API داخلی

`GET /api/v1/manage/provider-balances/kavenegar` و `GET /api/v1/manage/provider-balances/gapgpt` با نشست staff و مجوز `view_operations`، پاسخ `no-store` می‌دهند. سرویس ناشناخته404، نشست نامعتبر401 و نبود مجوز403است. سقف خواندن۳۰درخواست در دقیقه برای هر مدیر برقرار است.

پاسخ: `provider`, `status`, `amount`, `currency`, `observed_at`, `checked_at`, `reason`. وضعیت‌ها `available`, `stale`, `updating`, `unavailable`, `unsupported`, `not_configured`, `disabled` هستند. مبلغِ قابل دریافتِ کاوه‌نگار رشتهٔ صحیح ریال با `currency:IRR` است؛ برای GapGPT نامعلوم، مبلغ و واحد nullمی‌مانند. این مسیر یک proxy عمومی یا endpoint تغییر حساب نیست.

## بررسی محلی

۴۸۴ تست بک‌اند با PostgreSQL، ۶۶ تست فرانت و بررسی TypeScript موفق بودند. رابط در عرض‌های۳۷۵ و۱۴۴۰پیکسل با دادهٔ مستقل آزمون بررسی شد: تبدیل دقیق ریال به تومان، صفر واقعی، خطای بدون عدد صفر، موجودی قدیمی، مجوز عملیات، لینک رسمی، دسترسی با صفحه‌کلید و محصورماندن محتوا داخل کارت‌ها. این دادهٔ آزمون جایگزین نشست واقعی محصول نشد. مسیر HTTPS لوکال مدیریت200 و استعلام بدون نشست401است. فرانت با Fast Refresh به‌روز شد و راه‌اندازی مجدد نشد؛ پس از این بررسی، انتشار یکپارچهٔ۰٫۱۳٫۰ و آزمون HTTPS سرور نیز موفق شدند؛ جزئیات در گزارش انتشار آمده است.
