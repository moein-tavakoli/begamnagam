# انتشار۰٫۱۶٫۰ — ۲۰۲۶-۱۰-۳۰

کارفرما انتقال آخرین نسخه و همهٔ تغییرات جدید به prod و سرور را پس از موفقیت
CI صریحاً درخواست کرده است. این بسته همهٔ تغییرهای۰٫۱۴٫۱تا۰٫۱۶٫۰ را شامل
می‌شود: اصلاح نشست ورود پس از autofill، پیامک کوتاه چهاررقمی، ورودی شمارهٔ
وسط‌چین و محدود، رسید خلوت با نشان سبز، پنهان‌شدن منو در خانه، اعتبار زیر
شماره، اعلان اختیاری به‌روزرسانی و ورود مرحله‌ای سبک متن‌ها و کنترل‌های خانه.

ابتدا backend، frontend و compose برای همان commit تأیید می‌شوند و PR از
dev به prod با merge commit ادغام می‌شود. تصویر نهایی بک‌اند روی PostgreSQL
مجزا تست می‌شود؛ بکاپ رمز‌شده و بازیابی مستقل و بررسی مهاجرت‌ها قبل از استقرار
لازم‌اند. مهاجرت تازه‌ای نسبت به۰۰۳۵ وجود ندارد. تصویر فرانت از snapshot مجزا
ساخته می‌شود تا dev server و نشست آزمایش محلی کاربر برقرار بمانند.

شش فرانت با پل فایل‌های static و سپس تصویر نهایی به‌ترتیب جایگزین می‌شوند.
ظرفیت، تنظیمات خصوصی، کلیدها، داده، اعتبارها، سرویس واقعی OTP/SMS و خاموش‌بودن
پرداخت پولی حفظ می‌شوند. تست استقرار هیچ پیامک، پرداخت یا تماس پولی مدل ایجاد
نمی‌کند. بکاپ پس از استقرار هم بازیابی و صحت آن کنترل می‌شود؛ نسخهٔ قبلی برای
بازگشت باقی می‌ماند.

نتیجهٔ واقعی اجرا، CI، PR، شناسهٔ prod و تصاویر و گزارش امن بکاپ/HTTPS/مرورگر
در [صفحهٔ انتشار](https://github.com/moein-tavakoli/begamnagam/releases/tag/v0.16.0)
ثبت می‌شوند. وجود این سند به‌تنهایی به‌معنی پایان استقرار نیست. بررسی مرورگر
مستقل، جای دریافت پیامک روی گوشی فیزیکی را نمی‌گیرد؛ دامنه و مسیر شبکهٔ واقعاً
آزموده‌شده در گزارش مشخص می‌شوند.

Context7 در نشست انتشار در دسترس نبود؛ روال انتشار قبلی و مستندات رسمی
[Compose up](https://docs.docker.com/reference/cli/docker/compose/up/)،
[ادغام PR با تطبیق commit](https://cli.github.com/manual/gh_pr_merge) و
[فرمان‌های Django](https://docs.djangoproject.com/en/5.2/ref/django-admin/)
مبنای عملیات هستند.
