# نسخه۰٫۴٫۰ — اتصال‌ها و قراردادهای فاز۳

مجوز توسعه تا فاز۶ در AUTHORIZATION.json ثبت است؛ آزمون‌های انسانی به دستور کارفرما به پایان موکول شده‌اند. محدودیت push همچنان برقرار است.

## تحویل فنی

- کلاینت‌های HTTP کاوه‌نگار برای OTP، ارسال تک‌گیرنده و استعلام messageid/localid؛ کلاینت زرین‌پال برای request/verify/inquiry/reverse. کلید یا پاسخ خام در log/فرانت نمی‌آید. timeout محدود، خواندن پاسخ محدود و redirect غیرفعال است. مقصد شبکه فقط loopback قرارداد یا دامنه رسمی HTTPS است.
- مبلغ منبع داده عدد صحیح تومان است؛ مرز زرین‌پال صریحاً ریال با ضرب۱۰ است. query برگشت درگاه مدرک پرداخت نیست؛ سرور مبلغ ثبت‌شده را با درگاه verify می‌کند و فقط سپس capture و outbox می‌سازد. callback جعلی یا دوباره، ارسال/برداشت دوم نمی‌سازد.
- درخواست ساخت پرداخت با نتیجه نامعلوم خودکار تکرار نمی‌شود. authority موجود استعلام می‌شود؛ authority گم‌شده نیاز به تطبیق اپراتور دارد. نتیجه دیررس یا اضافه‌دریافت، تعهد refund می‌سازد و ارسال تازه نمی‌سازد.
- intent و lease ارسال قبل شبکه پایدارند؛ پس از timeout/مرگ worker فقط استعلام می‌شود. فقدان localid در پنجره۱۲ساعته دلیل ارسال مجدد نیست. فقط وضعیت صریح تحویل، «رسیده به گیرنده» است؛ accepted و unknown مستقل‌اند.
- بودجه روزانه ناخالص در PostgreSQL با قفل ردیف و شناسه عملیات کنترل می‌شود. retry همان عملیات رزرو دوباره ندارد؛ refund بودجه مصرف سرویس‌دهنده را باز نمی‌کند. محیط واقعی بدون سقف مثبت و فهرست شماره‌های داوطلب فعال نمی‌شود.
- UI مسیر انتقال به درگاه و نتیجه مالی/ارسال را دارد؛ hot reload حفظ شده است. اجرای جاری همچنان demo و بدون شبکه سرویس‌دهنده است.

## شواهد

۶۱ تست بک‌اند روی PostgreSQL/Redis بدون skip موفق شدند؛ شامل۱۵ تست HTTP قرارداد و مجموعه۱۲۰ مورد محتوایی قبلی. تست‌های قرارداد شامل جعلی/تکراری‌بودن callback، مبلغ متفاوت، موفقیت دیررس، قطع پاسخ پس از پذیرش، مرگ worker با lease، جلوگیری از ارسال دوم، سقف بودجه، redirect و OTP بدون debug هستند. فرانت۱۰ تست و typecheck بررسی شدند.

این سرور شبیه‌ساز loopback است؛ نتیجهٔ آن **تست sandbox واقعی ارائه‌دهنده نیست**. محیط تست ارائه‌دهندگان، اعتبارنامه، نوع خط، تعرفه، قرارداد محتوا و روش refund پس از تسویه هنوز ارائه نشده‌اند. هیچ تماس، پیامک، هزینه، ساخت حساب یا تراکنش خارجی انجام نشده است.

`reverse` فقط برگشت پیش از تسویه است؛ تعهدات خارج پنجره یا نامعلوم به وضعیت باز برای اپراتور می‌روند. بدون قرارداد/فرایند قابل اثبات بازپرداخت پس از تسویه، انتشار واقعی بسته می‌ماند. G3 خارجی پذیرفته‌شده ادعا نمی‌شود؛ توسعه مستقل فازهای بعد با مجوز جدید ادامه دارد.

نمونه تنظیمات در `provider.env.example` است و هیچ secret یا فعال‌سازی پیش‌فرض ندارد. قرارداد شبکه محلی با `DJANGO_TESTING=1 python manage.py test core.test_providers` از backend آزموده می‌شود؛ برای آزمون قفل‌ها، PostgreSQL لازم است.
