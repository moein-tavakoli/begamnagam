# نسخه۰٫۶ — تمرین پایلوت و تثبیت جریان ارسال

این بسته بخش قابل اجرای محلی فاز پنج را تحویل می‌دهد. پایلوت انسانی انجام نشده است؛ هیچ داوطلب، پیامک واقعی یا انتقال وجه واقعی در این نتیجه وجود ندارد. نتیجه پذیرش G5 باز می‌ماند.

[خروجی ماشین‌خوان تمرین](SYNTHETIC-PILOT.json): دوازده سناریو موفق با Django Client و CSRF فعال و ارائه‌دهندگان HTTP روی loopback. هفت موضوع از ورود و پیش‌نمایش تا تأیید مستقل پرداخت و رسید تحویل تمرین شده‌اند. callback جعلی/تکراری ارسال اضافه ایجاد نکرد. توقف دریافت میان پرداخت و dispatch مانع SMS شد و بازپرداخت ثبت شد. گزارش ناشناس تکراری یک رسید ساخت؛ توقف/ازسرگیری مدیر ممیزی شد و حالت پایلوت مثبت و رد محتوای نامجاز آزموده شد.

هشت capture و یک refund مصنوعی، هفت درخواست محتوای مصنوعی و صفر درخواست خارجی ثبت شد. اعداد بودجه گزارش، داده شبیه‌سازی هستند و تعرفه واقعی محسوب نمی‌شوند. یک گزارش مصنوعی باز برای آزمایش عملیات باقی ماند؛ شکایت داوطلب واقعی نیست.

رضایت نسخه ثابت شرایط سمت سرور ثبت می‌شود. خرابی Redis ارسال را موقتاً متوقف می‌کند؛ سفارش پرداخت‌شده ولی ارسال‌نشده پس از۲۴ساعت منقضی و به بازپرداخت می‌رود. توقف/تعلیق درست پیش از تماس سرویس‌دهنده دوباره کنترل می‌شود. نتیجه مبلغ/واحد نامطابق نیازمند تطبیق می‌ماند. ۸۳ آزمون backend روی PostgreSQL/Redis موفق‌اند.

بازاجرا: ابتدا متغیرهای `BENCH_DATABASE_URL` و `PILOT_REDIS_URL` (پایگاه Redis شماره۱۳) را مطابق راهنمای `scripts/synthetic-pilot.py --help` برای محیط محلی جدا تعیین کنید. ابزار دیتابیس جدید با پیشوند `begamnagam_pilot_` می‌سازد؛ از دیتابیس کاربر استفاده نمی‌کند. خروجی JSON فاقد شماره، کد OTP و لینک خصوصی است.

بررسی‌های انسانی، رضایت داوطلبان، گوشی واقعی، لحن فارسی، تماس پشتیبانی و پذیرش خارجی سرویس‌دهندگان در چک‌لیست نسخه۰٫۷ نگه داشته می‌شوند. عبور خودکار از آن‌ها یا امضای کارفرما ادعا نمی‌شود.
