# نسخه۰٫۸٫۱۵ — ارسال واقعی هدیه

مجوز صریح کارفرما: حذف شبیه‌سازی از سایت فعال، OTP و پیام واقعی، ۳ هدیه برای هر شمارهٔ تأییدشده، پرداخت پولی بسته. تنظیمات محلی همچنان demo است. ارسال به شماره‌های معتبر به فهرست تست محدود نیست؛ کنترل محتوا، قطع دریافت، احراز شماره، CSRF، سقف ارسال و بودجه حفظ می‌شوند.

پروفایل مستقل `config.live_sms_settings`، پرداخت و شبکهٔ زرین‌پال را می‌بندد و فقط کاوه‌نگار را برای OTP و پیام بررسی‌شده فعال می‌کند. نیازمندی‌های پرداخت پولی حذف نشده‌اند. هیچ پرچم تأیید قرارداد، بازپرداخت، شرایط یا حریم خصوصی بدون بررسی به true تبدیل نشده است. نسخهٔ شرایط صرفاً snapshot رضایت کاربر را مشخص می‌کند.

پیش‌نمایش و سفارش قدیمی با شرایط آزمایشی امکان تبدیل‌شدن به ارسال واقعی ندارند. `launch_live_gifts` با قفل سراسری در توقف ارسال، ماندهٔ هدیهٔ حساب‌های صرفاً آزمایشی را یک‌بار اصلاح و سابقه ثبت می‌کند. سفارش‌های تاریخی و `delivered_demo` محفوظ می‌مانند و خودکار بازفرستاده نمی‌شوند.

رابط، راهنما، سیاست نمایش‌داده‌شده، متا و کارت اشتراک‌گذاری با حالت واقعی هماهنگ شده‌اند. با اتمام۳هدیه، دکمه و API ارسال پولی بسته‌اند. فایل‌های SEO قبلی شامل canonical دامنه، JSON-LD، robots و sitemap همراه همین فرانت منتشر می‌شوند؛ صفحات خصوصی noindex می‌مانند.

## بررسی و استقرار

بک‌اند/فرانت۰٫۸٫۱۵ روی CT با هر۸کانتینر سالم مستقر و symlink جاری به نسخهٔ جدید منتقل شد. شناسهٔ PostgreSQL، Redis و RabbitMQ ثابت ماند؛ پیش از تغییر، نسخه/env و dump رمز‌شدهٔ دیتابیس حفظ شدند. migration تازه لازم نبود. ۷ماندهٔ مصرف‌شده فقط در demo به۳برگشت و۸فاصلهٔ ناشی از ارسال صرفاً آزمایشی پاک شد؛ قطع دریافت و تاریخچه حفظ شدند. هر۱۰حساب در پایان فعال‌سازی۳هدیه داشتند.

۱۶۰آزمون PostgreSQL/Redis در دیتابیس مجزای تست موفق‌اند. مسیر واقعی OTP→پیش‌نمایش→رضایت→سفارش رایگان→ارسال با transport ساختگی و rollback کامل داده/بودجه روی تنظیمات واقعی موفق بود. ۲۴آزمون فرانت، typecheck و build انتشار موفق‌اند. بررسی HTTPS از Nginx مرکزی با اعتبارسنجی عادی گواهی، ۳۰مسیر/asset، CSRF، cookie امن، canonical/JSON-LD، robots/sitemap و noindex خصوصی را پوشش داد. نبودن یک فایل JS مسیر metadata در runtime قدیمی هنگام پذیرش شناسایی و با وابستگی‌های trace‌شدهٔ همین build رفع شد؛ وابستگی‌های native لینوکس حفظ شدند. رابط در۳۷۵و۱۴۴۰پیکسل با دادهٔ ساختگی بررسی شد. این تست، پذیرش نصب روی گوشی واقعی نیست.

## مانع خارجیِ مشاهده‌شده

کارفرما یک پیامک واقعی قدردانی به شمارهٔ خودش با لینک قطع دریافت را صریحاً مجاز کرد. یک فراخوانی واقعی، بدون مصرف هدیهٔ حساب و با رزرو۲۰٬۰۰۰ریال از سقف موجود، با `sms_rejected_420` رد شد؛ پذیرش یا تحویل واقعی ثبت نشده است. مطابق [جدول خطاهای رسمی کاوه‌نگار](https://kavenegar.com/rest.html)، کد۴۲۰ یعنی حساب اجازهٔ ارسال لینک در متن را ندارد. پیام بدون لینک OTP این محدودیت را آشکار نمی‌کرد. درخواست دوباره ارسال نشد؛ لینک قطع دریافت نیز حذف یا مبهم نشد.

پس از این نتیجه، پیام نهایی با SafetyControl و alert عملیاتی `provider_link_permission` متوقف شد؛ OTP فعال و پرداخت پولی بسته است. مجوز ارسال لینک دامنهٔ `begamnagam.ir` باید در حساب کاوه‌نگار فعال شود. این مجوز در API مستندشدهٔ تنظیمات وجود ندارد و نشست واردشدهٔ پنل هم در مرورگر حاضر نبود. بعد از رفع آن، alert باید با سابقه بسته، ارسال ازسرگرفته و یک آزمون واقعی تازه انجام شود. نتیجهٔ کلی «استقرار موفق، ارسال واقعی در انتظار مجوز provider» است؛ نباید موفقیت تست نرم‌افزاری به‌عنوان تحویل پیامک گزارش شود.

حساب سرویس‌دهنده در حالت debug نبود و اعتبار یک سقف پیامک را داشت. گزینهٔ `resendfailed` روشن بود؛ برای حفظ ارسال یکتا و سقف هزینه، با API مستندشده خاموش و سابقه ثبت شد. سایر تنظیمات حساب تغییر نکردند. سقف روزانه همچنان۱۰۰٬۰۰۰ریال است و رزرو تلاش ردشده طبق سیاست محافظه‌کارانه پاک نشده است.

دسترسی معمول دامنه از این LAN همچنان Connection refused می‌دهد؛ بررسی از مسیر Nginx مرکزی با همان نام دامنه و TLS انجام شده است. [شواهد استقرار](../deployments/ct115-0.8.15.json) نتیجه‌های تفکیک‌شده را دارد.

Context7 در این نشست در دسترس نبود. مستندات رسمی Django۵٫۲، Compose و API کاوه‌نگار و راهنمای همراه Next۱۶٫۴٫۳ مرجع پیاده‌سازی بودند.

## بازگشت

قبل از بازگشت، ارسال را متوقف کنید. هر ارسال واقعی `accepted/submitting/unknown` باید با همین نسخه تطبیق داده شود؛ به‌هیچ‌وجه برای رفع ابهام دوباره ارسال نکنید. سپس نسخه و env قبلی را با هم بازگردانید. بازگشت نرم‌افزار، بودجه یا پیامک واقعی انجام‌شده را برنمی‌گرداند و هدیه را دوباره شارژ نمی‌کند. داده و volumeها حذف نمی‌شوند.
