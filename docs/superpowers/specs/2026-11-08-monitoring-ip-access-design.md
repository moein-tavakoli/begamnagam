# IPهای مجاز مانیتورینگ

درخواست کاربر: در تنظیمات سامانه IP تعریف شود تا تنها مانیتورینگ بدون ورود
برای آن IP باز شود؛ در باقی شبکه‌ها ورود مدیر و مجوز عملیات لازم بماند.

رویکرد: فهرست دقیق IPv4/IPv6 در یک تنظیم مستقل و پیش‌فرض خالی، قابل ویرایش
فقط توسط مدیر اصلی در «تنظیمات سایت». هر خط یک IP، حداکثر۵۰مورد؛ بدون CIDR،
دامنه یا wildcard. نوشتن با CSRF، شمارهٔ نسخه، قفل تراکنش و سابقهٔ مدیریتی.
پراکسی و loopback قابل اعطای دسترسی نیستند. هیچ IP خودکار اضافه نمی‌شود.

سرور در هر خواندن آمار، ورودِ مدیر دارای view_operations یا IP تطبیق‌یافته
را بررسی می‌کند. IP فقط از REMOTE_ADDR پس از میان‌افزار پراکسی موجود گرفته
می‌شود؛ هدر مستقیم کلاینت مجوز نیست. پراکسی شناخته‌شده بدون IP معتبر و خطای
خواندن تنظیمات به دسترسی بدون ورود منجر نمی‌شوند. مسیر صفحه گیت مستقل دارد
تا نه نشست مدیر بسازد و نه فهرست منوها را برای شبکهٔ مجاز باز کند.

صفحه/API آمار فقط تجمیعی، بدون اطلاعات خصوصی افراد و no-store است. تنظیمات،
داشبورد مدیریت، کاربران، پشتیبانی، متن‌ها، API محصول و Swagger خارج از این
استثنا هستند. حذف IP در درخواست بعدی اثر دارد؛ دادهٔ صفحه با پاسخ عدم دسترسی
پاک می‌شود. چیدمان فعلی MUI و دورهٔ۳۰ثانیه‌ای حفظ می‌شوند.

فهرست در دیتابیس پایدار است؛ هیچ کوکی ورود یا توکنِ دسترسی از IP صادر نمی‌شود.
لینک ثابت /manage/monitoring کافی است. نصب روی سرور درخواست جداگانه می‌خواهد.

تصمیم فنی: کنترل در Django انجام شود؛ کنترل صرفاً در فرانت قابل دورزدن است و
فهرست ثابت در پراکسی، مدیریت از داخل تنظیمات را فراهم نمی‌کند.
