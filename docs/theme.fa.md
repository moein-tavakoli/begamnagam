# تم روشن و تیره — در حال توسعه روی dev

با الهام از مرجع بصری `lumen-toggle.mp4`، دکمهٔ ماه/خورشید با قاب برجسته
کنار پروفایل صفحهٔ اصلی و، در صفحات داخلی، پس از لوگوی هدر قرار دارد.
پس از انتخاب، تم تازه با دایره‌ای از مرکز همان دکمه در هر دو جهت پخش می‌شود؛
شعاع تا دورترین گوشهٔ viewport محاسبه می‌شود. مدت حرکت حدود ۶۲۰ میلی‌ثانیه
با شروع و پایان نرم است. محتوای صفحه کپی یا دوباره بارگذاری نمی‌شود؛
snapshot مرورگر در انیمیشن استفاده می‌شود و دادهٔ فرم‌ها حفظ می‌شود.

## انتخاب و ذخیره

ترجیح `light` یا `dark` در کلید `begamnagam.theme` در localStorage همین
مرورگر ثبت می‌شود. پیش از انتخاب صریح، تم و تغییرات تم سیستم دنبال می‌شوند.
پس از انتخاب، ترجیح دستگاه بر سیستم مقدم است؛ ورود/خروج حساب آن را پاک
نمی‌کند. تب‌های همان مبدأ با رویداد storage هماهنگ می‌شوند. ذخیرهٔ مسدودشده
مانع تغییر تم در نشست جاری نیست؛ این ترجیح شخصی به API ارسال نمی‌شود.

اسکریپت ثابت ابتدای HTML با nonce فعلی CSP، تم را پیش از نخستین نمایش تنظیم
می‌کند. فقط تفاوت قابل انتظار `data-theme` روی html از هشدار hydration مستثنا
است. متای theme-color متعلق به کنترل‌کنندهٔ تم است تا cache متادیتای React
متای لایت تکراری ایجاد نکند؛ یکتایی و رنگ درست آن پس از تغییر مسیر بررسی شد.
سیاست CSP و جلوگیری از اسکریپت‌های دلخواه حفظ شده‌اند.

## رنگ و دسترس‌پذیری

زمینه، کارت‌ها، ورودی‌ها، OTP، منو، پیام‌ها، ترجیحات، تعرفه‌ها و پشتیبانی
از متغیرهای مشترک تم استفاده می‌کنند. حالت تیرهٔ صفحهٔ اصلی، پس‌زمینهٔ بنفش
تیره و متن روشن دارد؛ تصویر نامه و رنگ نشان برند حفظ می‌شوند. مدیریت Next.js
با ظاهر مستقل روشن خودش باقی می‌ماند؛ ادمین Django کنترل تم مستقل خودش را دارد.

دکمه برچسب ثابت «تم تیره» و حالت `aria-pressed` دارد؛ tooltip عمل بعدی را
توضیح می‌دهد. ناحیهٔ لمس حداقل ۴۴ پیکسل، فوکوس و کار با Space/Enter حفظ‌اند.
هنگام انیمیشن، انتخاب تکراری نادیده گرفته می‌شود و فوکوس کیبورد از دکمه
گرفته نمی‌شود. کاهش حرکت، نبود View Transition API یا شکست snapshot باعث
تغییر فوری و کامل تم می‌شود؛ فعال‌کردن کاهش حرکت وسط انیمیشن هم آن را متوقف می‌کند.

## بررسی محلی ۲۰۲۶-۱۰-۲۹

- ۷۰ تست فرانت و TypeScript موفق‌اند؛ سرور بومی Next.js حین ویرایش روشن ماند.
- مبدأ واقعی دکمه، پوشش تمام viewport، رفت‌وبرگشت روشن/تیره، حفظ انتخاب پس از
  reload و تغییر مسیر، هماهنگی تب‌ها، ترجیح سیستم و اولویت انتخاب صریح بررسی شدند.
- عرض‌های ۳۲۰، ۳۷۵، ۴۷۷، ۷۰۰، ۱۴۴۰ و حالت افقی بررسی شدند؛ منو و کنترل‌ها
  بیرون‌زدگی افقی یا تداخل با دکمهٔ پشتیبانی ندارند و کنترل‌های بالای خانه جدا هستند.
- کاهش حرکت، نبود API، snapshot ناموفق، localStorage مسدود و اجرای اسکریپت
  اولیه بدون bundleهای hydration بررسی شدند؛ خطای hydration یا CSP مشاهده نشد.
- OTP در نشست آزمون جدا با provider ساختگی بررسی شد: رنگ سطح و رقم عوض شد،
  مقدار ورودی `123456` حفظ شد و پیامک واقعی برای آزمون ارسال نشد.
- نسبت کنتراست نمونه‌های متن پروفایل/ورود و نوشتهٔ منوی تیره بیش از ۴٫۵ به ۱ بود.

این بررسی در dev است؛ نصب PWA، صفحهٔ آفلاین مستقل و ساخت انتشار از این
Hot Reload استنتاج نمی‌شوند. انتشار روی سرور انجام نشده است.

مبنای مرورگر، [مستند رسمی View Transition API](https://developer.mozilla.org/en-US/docs/Web/API/View_Transition_API/Using)
و مبنای آماده‌سازی پیش از نمایش، راهنمای نصب‌شدهٔ Next.js در
`frontend/node_modules/next/dist/docs/01-app/02-guides/preventing-flash-before-hydration.md` است.
