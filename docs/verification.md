# گزارش اعتبارسنجی محلی

تاریخ: ۲۴ اکتبر ۲۰۲۶. نتیجهٔ آزمون محلی با نتیجهٔ CI روی GitHub یا آمادگی انتشار عمومی یکی نیست. وضعیت سرویس‌های واقعی در فازبندی آمده است.

## بک‌اند

۳۲ تست روی PostgreSQL 17 و Redis واقعی با موفقیت اجرا شدند؛ هیچ تستی در اجرای PostgreSQL رد یا skip نشد. پایگاه آزمایشی پس از آزمون حذف و Redis روی database 15 ایزوله شد.

موارد پوشش‌داده‌شده:

- نشست، CSRF و چرخش توکن پس از ورود؛ انقضا، تلاش اشتباه، یک‌بارمصرف‌بودن و اتصال OTP به نشست.
- ورود مدیر و سپس تأیید شمارهٔ محصول، همراه انتقال درست پیش‌نمایش به نشست جدید.
- پیش‌نمایش زمان‌دار، مالکیت، مبلغ و متن ثبت‌شده و بی‌اثر بودن تغییر مبلغ سمت کلاینت.
- idempotency سفارش و پرداخت؛ اجرای هم‌زمان درخواست‌های تکراری با قفل‌های PostgreSQL.
- outbox، شکست انتشار در broker و پردازش تکراری worker بدون ارسال دوم.
- توقف دریافت پیش از خرید، پیش از پرداخت و پیش از worker؛ پاسخ عمومی برای علت‌های خصوصی گیرنده.
- محدودیت فرستنده، رزرو گیرنده و کنترل پایگاه داده حتی پس از پاک‌شدن کش.
- ارقام فارسی/عربی، رمزنگاری شماره، خروجی محدود مدل، خطای مدل و رد محتوای ممنوع.
- پذیرش فقط متن‌های بررسی‌شده در worker، برچسب `delivered_demo` و جلوگیری از فعال‌شدن پرداخت یا OTP واقعی.

بررسی تنظیمات Django، سازگاری migration، جمع‌آوری static و بررسی تنظیم امن با providerهای غیرفعال نیز موفق‌اند. اجرای سبک SQLite، تست‌های قفل PostgreSQL را skip می‌کند؛ نتیجهٔ PostgreSQL مبنای این گزارش است.

## محدودیت محیط وابستگی

نسخه‌های Django 5.2.18، Celery 5.6.3 و psycopg 3.3.6 در محیط مجازی نصب و آزموده شدند. `cryptography==46.0.7` در فایل نصب pin است، اما دانلود wheel آن در محیط حاضر مکرراً timeout شد؛ آزمون محلی موقتاً با نسخهٔ موجود 44.0.2 انجام شد. این نتیجه جای آزمون image نهایی با تمام نسخه‌های pin‌شده را نمی‌گیرد.

Context7 MCP به علت اتمام سهمیه مستندات نداد؛ مراجع رسمی و آزمون اجرا استفاده شدند. دریافت dependency و DNS در مرحلهٔ build Docker نیز در این محیط ناپایدار بود و تلاش‌های ساخت image به خطای شبکه برخوردند. پیکربندی Compose و گردش‌کارها بررسی شده‌اند، اما build کامل imageها و راه‌اندازی تمام اجزا با فایل اصلی Compose در این محیط تأیید نشده است. اجرای native فرانت و بک‌اند همراه سرویس‌های داده و صف کانتینری، مبنای تست انتهابه‌انتهای زیر است.

## مسیر API

تست دود در اجرای مستقیم روی API محلی موفق بود: ورود، پیش‌نمایش، ساخت و بازیابی سفارش تکراری، پرداخت آزمایشی، سابقه با شمارهٔ پوشیده، ترجیح دریافت و عدم دسترسی حساب دیگر. این چرخه هم در حالت سبک SQLite/eager و هم با PostgreSQL و Redis کانتینری و **RabbitMQ و worker مستقل Celery** موفق بود؛ log worker پردازش یک outbox و نتیجهٔ `delivered_demo` را ثبت کرد.

برای تست صف در این محیط، image از پیش موجود RabbitMQ 4.2.9 استفاده شد؛ فایل اصلی Compose برای نصب جدید RabbitMQ 4.4 را مشخص می‌کند. دریافت image جدید به علت شبکه تکمیل نشد؛ تست نسخهٔ قدیمی‌تر، تأیید image 4.4 محسوب نمی‌شود.

## فرانت و اتصال کامل

نصب از lockfile تکمیل و build production و TypeScript فرانت موفق شدند. هفت تست فرانت، استانداردسازی شماره، وضعیت سفارش، هدر CSRF و idempotency، UUID در مرورگر موبایل و خطاهای سرویس را پوشش می‌دهند.

تست دود از **`http://localhost:3000` از مسیر Next.js** نیز با بک‌اند PostgreSQL/Redis و RabbitMQ/worker مستقل موفق بود. بنابراین cookie و چرخش CSRF، rewrite API، ورود، پیش‌نمایش، پرداخت آزمایشی و نتیجهٔ صف در مسیر واقعی کلاینت بررسی شدند. صفحهٔ اصلی و manifest با HTTP 200 پاسخ دادند و پنل مدیریت به صفحهٔ ورود هدایت شد.

مسیر واقعی مرورگر دسکتاپ از انتخاب موضوع تا OTP با ارقام فارسی، پیش‌نمایش، سفارش و نتیجهٔ Celery و تاریخچه بررسی شد. قبل از تأیید صریح سفارش ساخته نشد، فرم تودرتو وجود نداشت و توقف دریافت پس از reload باقی ماند؛ فعال‌سازی دوباره نیز موفق بود. پنل مدیریت و CSS آن از پروکسی با HTTP 200 باز شدند. کنسول مرورگر در این مسیر خطا یا warning نداشت.

نمایش در اندازه‌های 375×812، 768×1024 و 812×375 بدون اسکرول افقی بررسی شد؛ فونت محلی بارگذاری شد و reduced motion حرکت نرم را غیرفعال کرد. رد محتوا با HTTP 422 خطای قابل‌فهم و دارای focus نشان داد و پس از اصلاح متن مسیر ادامه یافت. شبیه‌سازی قطع bootstrap ارسال را غیرفعال کرد و retry موضوع‌های فعال را بازگرداند. logout سابقه را پاک کرد. خطاهای کنسول این سناریوهای منفی فقط مربوط به درخواست‌های عمداً ردشده یا قطع‌شده بودند؛ خطای React یا JavaScript مشاهده نشد.

بررسی syntax گردش‌کارهای GitHub با actionlint و `docker compose config --quiet` موفق بود. هیچ push یا اجرای CI در GitHub انجام نشده است.

## مرز پذیرش

هیچ سرویس پیامک یا درگاه واقعی فراخوانی نشده است. تست مدل با پاسخ ساختگی، صحت قرارداد و رفتار خطا را بررسی می‌کند؛ اجرای واقعی Ollama و کیفیت انتخاب متن به مدل نصب‌شده نیاز دارد. بار ۱۰۰۰ کاربر هم‌زمان تست نشده و جزو ادعای نسخهٔ اولیه نیست. بار هدف فعلی، ۱۰۰۰ حساب عمدتاً غیرفعال است.

## گسترش پیام‌های مثبت

موضوع‌های تشکر و قدردانی، دلگرمی و تشویق، و تبریک و شادی در ابتدای فهرست قرار گرفتند و قدردانی انتخاب پیش‌فرض شد. هر سه مسیر در آزمون یکپارچه تا نتیجه `delivered_demo` بررسی شدند. پس از این تغییر، هر ۳۲ تست بک‌اند روی PostgreSQL/Redis و هفت تست فرانت و typecheck/build موفق بودند. تست دود از Next.js با موضوع جدید دلگرمی، RabbitMQ و worker مستقل نیز موفق شد. در مرورگر اجرای فعلی، هر هفت موضوع و انتخاب پیش‌فرض قدردانی دیده شدند. ارسال واقعی انجام نشد. تصمیم حفظ HTTP polling به جای افزودن WebSocket در معماری ثبت شد.
