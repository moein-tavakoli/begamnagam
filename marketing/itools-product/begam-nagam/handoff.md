# تحویل بستهٔ معرفی بگم نگم به آیتولز

این بسته برای قالب موجود محصولات iTools / آیتولز است. متن نهایی در `product-content.json` و نسخهٔ خوانا با همان ترتیب و عبارات در `product-copy.fa.md` قرار دارد. نسخهٔ مستندات محلی `0.16.2` است؛ تمام تصاویر از محصول `0.16.1` و commit `4c1ffceae5b10421b0f2f0fc134f402ead270b8b` ثبت شده‌اند. افزایش شمارهٔ بسته، ادعای انتشار سرور نیست.

## فایل‌های تحویل و انتقال

| فایل | کاربرد |
| --- | --- |
| `product-content.json` | محتوای آمادهٔ قالب موجود؛ مطابق schema خوانده‌شده از سایت شرکت |
| `product-copy.fa.md` | نسخهٔ انسانی تمام مقادیر JSON، بدون بازنویسی متفاوت |
| `images/` | ۱۲ WebP تأییدشده؛ فقط این پوشه برای تصاویر عمومی محصول |
| `logo.svg` | کپی دقیق آیکون موجود محصول؛ لوگوی تازه یا wordmark مستقل نیست |
| `screenshots-manifest.json` | alt/caption/زمان/نسخه/حجم/ابعاد/سناریو/SHA و وضعیت انتشار هر عکس |
| `capabilities-inventory.md` | ۲۱ قابلیت با مسیر، وضعیت، وابستگی و منبع |
| `evidence.md` | مبنای ادعاها، اختلاف اسناد و مرز اجرای آزمایشی و واقعی |
| `qa/` | شواهد و ابزار بازتولید؛ در public سایت کپی نشود |

برای انتقال بعدی، محتوای JSON را در ورودی مورد استفادهٔ قالب فعلی شرکت وارد کنید. هر `images/<filename>.webp` به `frontend_next/public/images/products/begam-nagam/<filename>.webp` می‌رود؛ در JSON مسیرها از `/images/products/begam-nagam/` شروع می‌شوند. لوگو در JSON کلید جدا ندارد و فقط در جایگاه واقعی دارایی برند سایت استفاده می‌شود. `sourceProductId` تا تعیین شناسهٔ واقعی Django Product شرکت `null` بماند؛ شناسهٔ حساب/سفارش بگم نگم جایگزین آن نیست.

هیچ فایل سایت شرکت در این کار تغییر نکرده و هنوز محتوا در آن import یا منتشر نشده است. `visual=chat` برچسب ماهیت محصول نیست. `modules` عمداً خالی است. CTA به `/#requestSupport` اشاره می‌کند و متن آن «درخواست معرفی محصول» است.

## انتخاب تصویر و ترتیب گالری

**Hero:** `desktop-reminder-compose.webp`، ۱۶۰۰×۱۰۰۰، فرم واقعی یادآوری در تم تیره. **کارت:** `desktop-appreciation-compose.webp`، تصویر مستقل ۱۶۰۰×۱۰۰۰ با نمونهٔ قدردانی. هر دو نسبت ۱۶:۱۰ دارند و باید با `contain` نمایش داده شوند؛ برش لازم نیست. فضای اطراف فرم بخشی از چیدمان واقعی دسکتاپ است.

ترتیب گالری همان ترتیب JSON است:

1. `mobile-home.webp` — نقطهٔ شروع مشترک.
2. `mobile-reminder-draft.webp` — انتخاب نمونهٔ یادآوری.
3. `mobile-reminder-preview.webp` — مقصد مصنوعی و مرور متن نهایی.
4. `mobile-reminder-receipt.webp` — رسید ثبت آزمایشی.
5. `mobile-appreciation-preview.webp` — مرور متن قدردانی.
6. `desktop-history.webp` — نتیجهٔ همین دو سناریو در سابقه.
7. `mobile-recipient-preferences.webp` — حساب مستقل گیرنده و توقف دریافت.
8. `desktop-pricing.webp` — بسته‌های پایگاه آزمایشی، با caption روشن دربارهٔ قیمت نمایشی.

سه عکس یادآوری از draft تا preview تا receipt مراحل متوالی یک اجرای واقعی‌اند. تصویر سابقه پس از پایان قدردانی گرفته شد و هر دو درخواست را نشان می‌دهد. قدردانی از انتخاب نمونه تا رسید هم اجرا شد، ولی برای گالری فقط preview و سابقهٔ مشترک انتخاب شده‌اند. دو نمای فرم دسکتاپ برای hero/card بازدید بعدی از فرم هستند و نباید به‌عنوان مراحل پیشین همان دنبالهٔ موبایل زمان‌بندی شوند.

شش نمای عمودی ۷۸۰×۱۶۸۸ واقعاً در viewport موبایل ۳۹۰×۸۴۴ ثبت شده‌اند. نسبت اصلی و caption آزمایشی آن‌ها حفظ شود. `desktop-support.webp` و `desktop-demo-credit.webp` مکمل اختیاری‌اند؛ گالری فعلی هشت ورودی دارد. خرید مکمل بعد از دریافت پاداش دعوت گرفته شد، به همین دلیل چهار هدیه و سه اعتبار آزمایشی دارد؛ سابقهٔ زودتر فقط یک هدیه داشت.

`qa/desktop-hero.webp` رد شده است: جای‌نگهدار نشان اینماد/درگاه در صفحهٔ آغاز دسکتاپ، تأیید رسمی یا اتصال فعال نیست. آن را منتشر نکنید. `qa/qa-freeform-unavailable.png` صرفاً شاهد خطای کنترل‌شده با متن خنثی است. این رد/شاهدها در manifest مشخص‌اند و داخل `images/` نیستند. برای پوشاندن وضعیت واقعی، DOM یا UI اصلاح نشد. تم تیره در محصول وجود دارد و همان استفاده شده است.

## بازتولید دموی مستقل و بدون سرویس واقعی

پیش‌نیاز: checkout مخزن دارای commit مبنا، محیط `backend/.venv` با وابستگی‌های قفل‌شده و `frontend/node_modules` موجود. اسکریپت هیچ وابستگی یا سرویس بیرونی را خودکار نصب نمی‌کند. از مرورگر/پروفایل جدا استفاده کنید؛ `.env`، پایگاه، cookie و حساب عملیاتی را وارد این محیط نکنید.

از ریشهٔ مخزن، یک پوشهٔ تازه و خالی برای runtime تعیین کنید:

```sh
python3 marketing/itools-product/begam-nagam/qa/run-demo.py \
  --repo . \
  --runtime .local/itools-capture-repeat
```

اسکریپت نسخهٔ ثابت تصاویر را با `git archive` جدا می‌کند، کلیدهای محلی موقت می‌سازد، migrations را روی SQLite تازه اعمال و Django/Next dev را اجرا می‌کند. پورت‌های ۳۱۳۷ و ۸۱۳۷ باید آزاد باشند؛ اگر مشغول‌اند، سرویس موجود را برای این کار متوقف نکنید. launcher تحویلی قبل از اجرا پورت و خالی‌بودن runtime را بررسی و Next را به loopback محدود می‌کند. رابط از `http://127.0.0.1:3137` باز می‌شود. این مسیر به‌طور صریح OTP demo، SMS/invitation console، payment demo و AI template دارد؛ credentialها خالی و شبکهٔ provider غیرفعال است. `demo.invalid` در متن پیام عمدی است.

بعد از آماده‌شدن رابط، bootstrap باید `demo_mode=true`، `otp_is_real=false`، `rewrite_mode=template` و `payment_backend=demo` نشان دهد. بازتولید کنترل مرورگر با Playwright نصب‌شده و Chrome محلی:

```sh
PLAYWRIGHT_PACKAGE='/absolute/path/to/node_modules/playwright' \
CHROME_EXECUTABLE='/Applications/Google Chrome.app/Contents/MacOS/Google Chrome' \
node marketing/itools-product/begam-nagam/qa/check-browser.cjs
```

مسیر Playwright را از نصب خودتان تعیین کنید؛ در این بررسی از runtime همراه Codex استفاده شد. ابزار روی مبدأ محلی ثابت است و ابتدا bootstrap را کنترل می‌کند؛ آن را برای سرویس واقعی تغییر ندهید. اجرای دوباره، گزارش QA و تصویر خطا را بازنویسی می‌کند؛ برای حفظ بستهٔ تحویلی روی یک کپی کار کنید. حساب‌های این ابزار فقط دادهٔ مصنوعی‌اند؛ از شمارهٔ خود یا مشتری استفاده نکنید. برای سناریوی اصلی، دو نمونه و ترتیب دقیق در `evidence.md` آمده‌اند. OTP را از پاسخ مجاز خود دموی محلی مصرف کنید و هیچ کد یا نشست را در خروجی نگه ندارید.

هنگام capture، desktop viewport برابر ۱۶۰۰×۱۰۰۰ با DPR=1 و mobile برابر ۳۹۰×۸۴۴ با DPR=2، colorScheme=dark و reducedMotion=reduce بود. بعد از بارگذاری قلم و پایان درخواست‌ها، از viewport واقعی screenshot گرفته و بدون crop/resize به WebP کیفیت ۸۸ تبدیل شد. برای اعتبار PWA، این dev server کافی نیست؛ این کار production build یا آزمون نصب انجام نداد.

در پایان Ctrl+C را در launcher بزنید، بسته‌شدن فرایندهای همان runtime را بررسی و فقط پوشهٔ جداگانه‌ای را که خودتان ساخته‌اید حذف کنید. runtime شامل دادهٔ مصنوعی، کلیدهای موقت و لاگ محلی است و نباید ZIP یا commit شود. حذف آن، قابلیت استفادهٔ دوباره از session و grant آزمایشی را از بین می‌برد. پاک‌سازی همین بررسی در `qa/cleanup.json` ثبت شده است.

## اعتبارسنجی بسته

`qa/product-landing.schema.json` snapshot همان قرارداد خوانده‌شده است. با Python دارای `jsonschema` و Pillow:

```sh
backend/.venv/bin/python marketing/itools-product/begam-nagam/qa/validate-package.py
```

این فرمان schema، enumها، تعداد و یکتایی، یکسانی متن خوانا با JSON، مسیر و هش تصاویر، ابعاد/حجم، لوگو و نبود فایل‌های runtime را بررسی می‌کند. گزارش `qa/validation.json` نتیجهٔ آخرین اجرای تحویل است. `qa/build-package.py` برای تولید دوبارهٔ متن خوانا/manifest از داده‌های capture موجود است؛ پس از تغییر عکس یا JSON باید بازبینی انسانی هم تکرار شود. اسکریپت اسمبلی تصویر تازه تولید یا ظاهر عکس را دستکاری نمی‌کند.

## تصمیم‌ها و پذیرش‌های باقی‌مانده

- شناسهٔ واقعی Product در سایت شرکت باید هنگام اتصال محتوا معلوم شود؛ فعلاً `null` صحیح است.
- نسخهٔ مستقر امروز، قیمت جاری، روش پرداخت فعال و دسترس‌پذیری providerها در محیط عمومی مستقلاً بررسی نشده‌اند. تا آن زمان توضیح «نسخهٔ بررسی‌شده/دموی مستقل» و caption قیمت حذف نشود.
- GapGPT اختیاری است؛ آزمون واقعی تاریخی کیفیت بی‌نقص را ثابت نکرده و prompt اصلاح‌شدهٔ اشاره‌شده در گزارش، paid retest نداشته است. نتیجهٔ AI جدید یا اتصال دائم ادعا نشود. مدل‌های محلی تأیید کیفیت نشده‌اند.
- نصب PWA، WebOTP و صفحه‌کلید روی گوشی فیزیکی، حالت آفلاین production، ممیزی کامل دسترس‌پذیری و هم‌زمانی صف در این کار آزموده نشده‌اند.
- نشان‌های اعتماد صفحهٔ آغاز دسکتاپ نیازمند بررسی جداگانهٔ محصول/مجوز واقعی‌اند؛ عکس ردشده مجوز نمایش گواهی نیست. در این درخواست UI تغییر نکرد.
- هیچ مانع حل‌نشده‌ای برای تحویل خود بسته وجود ندارد؛ import در سایت شرکت، انتشار، ارسال واقعی و استقرار خارج از این درخواست‌اند.
